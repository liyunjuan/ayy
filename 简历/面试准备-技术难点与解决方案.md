### 难点 1.1: WebSocket 频繁断线重连

**问题描述**：
- 用户网络不稳定，WebSocket 频繁断开
- 每次断开都立即重连，导致"重连风暴"
- 断线期间的消息丢失

**解决方案**：

```javascript
// 指数退避重连策略
class ReconnectStrategy {
  constructor() {
    this.attempts = 0;
    this.maxDelay = 30000;    // 最大延迟 30 秒
    this.baseDelay = 1000;    // 基础延迟 1 秒
    this.factor = 1.5;        // 增长因子
  }
  
  getDelay() {
    // 1s -> 1.5s -> 2.25s -> 3.375s -> ... -> 30s
    return Math.min(
      this.baseDelay * Math.pow(this.factor, this.attempts),
      this.maxDelay
    );
  }
  
  reconnect(ws) {
    const delay = this.getDelay();
    console.log(`Will reconnect in ${delay}ms (attempt ${this.attempts + 1})`);
    
    setTimeout(() => {
      this.attempts++;
      ws.connect();
    }, delay);
  }
  
  reset() {
    this.attempts = 0;
  }
}

// 消息队列缓存
const pendingMessages = [];

function sendMessage(message) {
  if (ws.readyState === WebSocket.OPEN) {
    ws.send(JSON.stringify(message));
  } else {
    pendingMessages.push(message);
  }
}

// 重连成功后批量发送
ws.onopen = () => {
  strategy.reset();
  
  while (pendingMessages.length > 0) {
    const msg = pendingMessages.shift();
    ws.send(JSON.stringify(msg));
  }
};
```

**关键点**：
- ✅ 指数退避避免重连风暴
- ✅ 消息队列保证不丢失
- ✅ 重连成功后批量发送

**面试话术**：
> "项目中遇到 WebSocket 频繁断线的问题，我通过实现指数退避重连策略和消息队列机制解决。具体来说，每次重连延迟按 1.5 倍递增，最大 30 秒，避免了重连风暴。同时用队列缓存断线期间的消息，重连后批量发送，保证消息不丢失。"

### 难点 1.2: YTalk 跨标签页通话冲突

**问题描述**：
- 用户打开多个标签页
- Tab A 正在通话，Tab B 也能接听来电
- 导致两个 Tab 争抢麦克风/扬声器资源

**解决方案**：

```javascript
// 使用 Broadcast Channel 同步状态
class YTalkSharedState {
  constructor() {
    this.channel = new BroadcastChannel('ytalk-channel');
    this.tabId = `tab-${Date.now()}-${Math.random()}`;
    this.state = {
      isInCall: false,
      activeTab: null
    };
    
    this.channel.onmessage = this.handleMessage.bind(this);
  }
  
  // Tab A 接听来电
  acceptCall(callUuid) {
    this.state.isInCall = true;
    this.state.activeTab = this.tabId;
    
    // 广播给其他 Tab
    this.channel.postMessage({
      type: 'CALL_ACCEPTED',
      callUuid,
      tabId: this.tabId
    });
  }
  
  // Tab B 收到广播，禁用通话功能
  handleMessage(event) {
    const {type, tabId} = event.data;
    
    if (type === 'CALL_ACCEPTED' && tabId !== this.tabId) {
      this.state.isInCall = true;
      this.disableCallButtons();
      this.showNotification('其他标签页正在通话');
    }
    
    if (type === 'CALL_ENDED') {
      this.state.isInCall = false;
      this.enableCallButtons();
    }
  }
  
  endCall() {
    this.state.isInCall = false;
    this.channel.postMessage({type: 'CALL_ENDED'});
  }
}

export default new YTalkSharedState();
```

**关键点**：
- ✅ Broadcast Channel 跨 Tab 通信
- ✅ 全局状态同步
- ✅ 资源互斥锁

**面试话术**：
> "YTalk 电话功能遇到跨标签页冲突的问题。我使用 Broadcast Channel API 实现了跨 Tab 状态同步。当 Tab A 接听来电时，通过 Broadcast Channel 广播给其他 Tab，其他 Tab 收到消息后自动禁用通话功能，实现资源互斥。"

### 难点 1.3: WebSocket 心跳超时判断

**问题描述**：
- 如何判断连接是否真正可用？
- 网络抖动导致误判
- 心跳频率和超时时间如何设置？

**解决方案**：

```javascript
class HeartbeatManager {
  constructor(ws) {
    this.ws = ws;
    this.interval = 30000;      // 30 秒发一次心跳
    this.timeout = 60000;       // 60 秒未响应判定超时
    this.timer = null;
    this.timeoutTimer = null;
  }
  
  start() {
    this.timer = setInterval(() => {
      // 发送心跳
      this.ws.send(JSON.stringify({
        type: 'PING',
        timestamp: Date.now()
      }));
      
      // 设置超时定时器
      this.timeoutTimer = setTimeout(() => {
        console.error('Heartbeat timeout, connection dead');
        this.ws.close(); // 主动关闭，触发重连
      }, this.timeout);
    }, this.interval);
  }
  
  // 收到 PONG 响应
  onPong() {
    clearTimeout(this.timeoutTimer);
  }
  
  stop() {
    clearInterval(this.timer);
    clearTimeout(this.timeoutTimer);
  }
}

// 使用
ws.onmessage = (event) => {
  const message = JSON.parse(event.data);
  
  if (message.type === 'PONG') {
    heartbeat.onPong();
  }
};
```

**关键点**：
- ✅ 30 秒发一次心跳（平衡频率和开销）
- ✅ 60 秒超时判定（容忍网络抖动）
- ✅ 超时主动关闭，触发重连

**面试话术**：
> "为了保证 WebSocket 连接可用性，我实现了心跳机制。每 30 秒发送一次 PING，如果 60 秒内未收到 PONG 响应，判定连接已死，主动关闭并触发重连。这个时间设置平衡了实时性和网络抖动容忍度。"

### 难点 2.2: Vuex Store 模块划分

**问题描述**：
- Store 文件过大（1000+ 行）
- 状态耦合严重
- 多人协作冲突频繁

**解决方案**：

```javascript
// store/index.js
import Vue from 'vue';
import Vuex from 'vuex';

// 模块化拆分
import user from './modules/user';
import config from './modules/config';
import chat from './modules/chat';
import ytalk from './modules/ytalk';
import ticket from './modules/ticket';
import customer from './modules/customer';

export default new Vuex.Store({
  modules: {
    user,
    config,
    chat,
    ytalk,
    ticket,
    customer
  }
});

// store/modules/chat.js
export default {
  namespaced: true, // 开启命名空间
  
  state: {
    conversations: [],
    messages: {},
    unreadCount: 0
  },
  
  getters: {
    currentConversation: (state) => (conversationId) => {
      return state.conversations.find(c => c.id === conversationId);
    },
    
    messagesByConversation: (state) => (conversationId) => {
      return state.messages[conversationId] || [];
    }
  },
  
  mutations: {
    ADD_CONVERSATION(state, conversation) {
      state.conversations.push(conversation);
    },
    
    ADD_MESSAGE(state, {conversationId, message}) {
      if (!state.messages[conversationId]) {
        Vue.set(state.messages, conversationId, []);
      }
      state.messages[conversationId].push(message);
    }

    async sendMessage({commit}, {conversationId, content}) {
      const message = await ChatAPI.send({conversationId, content});
      commit('ADD_MESSAGE', {conversationId, message});
    }
  }
};

// 组件中使用
import {mapState, mapActions} from 'vuex';

export default {
  computed: {
    ...mapState('chat', ['conversations', 'unreadCount'])
  },
  
  methods: {
    ...mapActions('chat', ['sendMessage'])
  }
};
```

**关键点**：
- ✅ 按业务域拆分模块
- ✅ 开启 namespaced 避免冲突
- ✅ Getters 封装计算逻辑

**面试话术**：

```javascript
    return {
      messages: [],
      page: 1,
      pageSize: 50,
      loading: false
    };
  },
  
  methods: {
    async loadMore() {

        conversationId: this.conversationId,
        page: this.page,
        pageSize: this.pageSize

        this.loadMore();
      }
    }
  }
};

  <img
    v-lazy="message.imageUrl"
    :data-src="message.imageUrl"
    class="chat-image"
  />
</template>

<script>

  throttleWait: 300

</script>
```

### 难点 3.3: 大文件上传卡顿

**问题描述**：
- 上传大文件（视频、录音）导致页面卡顿
- 进度条不准确
- 上传失败难以重试

**解决方案**：

```javascript
// 分片上传 + Web Worker
class ChunkUploader {
  constructor(file, options = {}) {
    this.file = file;
    this.chunkSize = options.chunkSize || 2 * 1024 * 1024; // 2MB
    this.chunks = Math.ceil(file.size / this.chunkSize);
    this.uploadedChunks = 0;
  }
  
  async upload(onProgress) {
    const uploadId = await this.initUpload();
    
    for (let i = 0; i < this.chunks; i++) {
      const chunk = this.file.slice(
        i * this.chunkSize,
        (i + 1) * this.chunkSize
      );
      
      await this.uploadChunk(uploadId, i, chunk);
      
      this.uploadedChunks++;
      onProgress({
        percent: (this.uploadedChunks / this.chunks) * 100,
        uploadedSize: this.uploadedChunks * this.chunkSize,
        totalSize: this.file.size
      });
    }
    
    return await this.completeUpload(uploadId);
  }
  
  async uploadChunk(uploadId, index, chunk) {
    const formData = new FormData();
    formData.append('uploadId', uploadId);
    formData.append('chunkIndex', index);
    formData.append('chunk', chunk);
    
    // 重试机制
    let retries = 3;
    while (retries > 0) {
      try {
        await axios.post('/api/upload/chunk', formData);
        return;
      } catch (error) {
        retries--;
        if (retries === 0) throw error;
        await this.delay(1000);
      }
    }
  }
  
  delay(ms) {
    return new Promise(resolve => setTimeout(resolve, ms));
  }
}

// 使用
const uploader = new ChunkUploader(file);

await uploader.upload(({percent}) => {
  this.uploadPercent = percent;
});
```

**关键点**：
- ✅ 2MB 分片上传，避免单次请求过大
- ✅ 失败自动重试 3 次
- ✅ 准确的进度回调

**面试话术**：
> "大文件上传采用分片上传方案，每片 2MB。这样既避免了单次请求过大导致的超时，又能实现断点续传。同时加了 3 次重试机制，提升上传成功率。进度条基于已上传分片数计算，非常准确。"

```javascript
import ConfigHub from '@yqg/config-hub';

// 2. Vuex Store 管理配置
// store/modules/config.js
export default {
  namespaced: true,
  
  state: {
    config: {},
    loading: false,
    error: null
  },
  
  mutations: {
    SET_CONFIG(state, config) {
      state.config = config;
    },
    SET_LOADING(state, loading) {
      state.loading = loading;
    },
    SET_ERROR(state, error) {
      state.error = error;
    }
  },
  
  actions: {
    async getConfig({commit}) {
      commit('SET_LOADING', true);
      
      try {
        const config = await ConfigHub.get({
          appId: APPID,
          countryCode: COUNTRY_CODE
        });
        
        commit('SET_CONFIG', config);
        return config;
      } catch (error) {
        commit('SET_ERROR', error);
        throw error;
      } finally {
        commit('SET_LOADING', false);
      }
    }
  }
};

// 3. 应用启动时加载
// bootstrap.js
async function initConfig() {
  await store.dispatch('config/getConfig');
}

async function main() {
  await initConfig();

    router,

  }).$mount('#app');
}

main();
```

## 5. 微前端类

### 难点 5.1: 主子应用样式隔离

**问题描述**：
- 子应用样式污染主应用
- 主应用全局样式影响子应用
- 第三方库样式冲突

**解决方案**：

```javascript
// 方案 1: micro-app 自动隔离（推荐）
<micro-app
  name="collection"
  url="https://collection.fintopia.tech"
  inline // 样式内联，自动隔离
></micro-app>

// 方案 2: 手动添加样式前缀
// postcss.config.js
module.exports = {
  plugins: [
    require('postcss-prefix-selector')({
      prefix: '.micro-app-collection',
      transform(prefix, selector) {
        return `${prefix} ${selector}`;
      }
    })
  ]
};

// 输出结果
.micro-app-collection .button {
  color: red;
}

// 方案 3: Shadow DOM（仅支持现代浏览器）
const shadowRoot = container.attachShadow({mode: 'open'});
shadowRoot.innerHTML = `
  <style>
    /* 子应用样式 */
  </style>
  <div class="app"></div>
`;
```

**关键点**：
- ✅ micro-app 自动样式隔离
- ✅ postcss 插件添加前缀
- ✅ Shadow DOM 天然隔离

**面试话术**：
> "微前端样式隔离采用 micro-app 的自动隔离方案，它会将子应用的样式内联并添加作用域。对于 iframe 方式的子应用，天然隔离。对于源码引入的模块，用 postcss-prefix-selector 插件添加 CSS 前缀。"

## 6. 工程化类

### 难点 6.1: Monorepo 依赖管理

**问题描述**：
- 子项目依赖版本不一致
- 重复安装依赖，磁盘占用大
- 共享层版本更新困难

**解决方案**：

```json
// 根 package.json
{
  "private": true,
  "workspaces": [
    "cs/common",
    "cs/ychat",
    "cs/ocs-client",
    "cs/ocs-admin"
  ],
  "resolutions": {
    "vue": "2.6.14",
    "vuex": "3.6.0",
    "axios": "0.24.0"
  }
}

// 子项目只声明特有依赖
// cs/ychat/package.json
{
  "name": "new-ychat",
  "dependencies": {
    "@yqg/ytalk-sdk": "0.0.5-beta.3", // 特有依赖
    "@yqg/seat-assist": "1.0.14"
  }
}
```

**命令**：
```bash
# 安装依赖（根目录）
yarn install

# 给特定子项目添加依赖
yarn workspace new-ychat add lodash-es

# 给所有子项目添加依赖
yarn workspaces run add vue-router

# 更新共享层
cd cs/common
git pull
yarn install
```

**关键点**：
- ✅ Yarn Workspaces 提升依赖
- ✅ resolutions 锁定版本
- ✅ 共享层独立维护

**面试话术**：
> "项目用 Yarn Workspaces 管理 Monorepo，公共依赖提升到根目录，避免重复安装。通过 resolutions 锁定关键依赖版本，保证一致性。共享层 @cs/common 独立维护，子项目通过路径别名直接引用。"

**问题描述**：

```bash
# Commit Message 规范
[模块][国家] type: 简短描述

[ychat][indo] fix: 修复新工作台灰度判断问题

refactor: 重构
patch: 小改动
docs: 文档
style: 格式
test: 测试
chore: 构建/工具

# Husky + Commitlint
// .husky/commit-msg
#!/bin/sh
yarn commitlint --edit $1

// commitlint.config.js
module.exports = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'subject-case': [0], // 允许任意大小写
    'type-enum': [
      2,
      'always',
      ['feat', 'fix', 'refactor', 'patch', 'docs', 'style', 'test', 'chore']
    ]
  }
};
```

**关键点**：
- ✅ 统一 Commit Message 格式
- ✅ Commitlint 自动校验
- ✅ 便于定位和回滚

**面试话术**：
> "项目制定了 Commit Message 规范：[模块][国家] type: 描述。通过 Husky + Commitlint 自动校验，不符合规范的提交会被拒绝。这样既便于生成 Changelog，也方便定位问题和回滚代码。"
