## 2. 技术选型类

### Q2.1: 为什么选择 Vue 2 而不是 Vue 3？

**回答**：

> 项目启动时（2021 年）的技术选型考虑：
>
> **选择 Vue 2 的原因**：
> 1. **生态成熟**：Vue 2 生态非常成熟，Ant Design Vue 1.x、内部组件库都是基于 Vue 2
> 2. **团队熟悉**：团队对 Vue 2 非常熟悉，迁移成本低
> 3. **稳定性**：Vue 2 经过多年验证，Bug 少，稳定性高
> 4. **Vue 3 不成熟**：当时 Vue 3 刚发布，生态不完善，很多库不支持
>
> **Vue 2 的优势（针对项目）**：
> 1. **Options API**：适合大团队协作，代码结构清晰
> 2. **生态丰富**：Ant Design Vue 1.x、Element UI、Vant 等
> 3. **稳定可靠**：经过多年生产环境验证
>
> **未来规划**：
> - 新模块考虑使用 Vue 3 + Composition API
> - 旧模块逐步迁移（非紧急）
> - 微前端架构支持 Vue 2 和 Vue 3 共存

## 3. 架构设计类

### Q3.1: 多国家架构是如何设计的？

**回答**：

> **设计思路**：通过**三层控制**实现多国家支持
>
> **第一层：国家判断**
> ```javascript
> // 环境变量 + 域名 + URL 参数
> export const isIndo = /indo/i.test(STAGE) || 
>                      /indo/i.test(location.hostname) || 
>                      new URL(location.href).searchParams.get('locale') === 'indo';
> ```
>
> **第二层：路由控制**
> ```javascript
> // 路由 Meta 声明
> {
>   path: '/cash-loan',
>   meta: {
>     businessCode: ['cn'] // 仅国内可见
>   }
> }
> 
> // 路由守卫拦截
> router.beforeEach((to, from, next) => {
>   if (!to.meta.businessCode.includes(currentCountry)) {
>     return next('/404');
>   }
>   next();
> });
> ```
>
> **第三层：配置中心**
> ```javascript
> // 运行时动态加载配置
> const config = await ConfigHub.get({
>   appId: APPID,
>   countryCode: COUNTRY_CODE
> });
> ```
>
> **第四层：国际化**
> ```javascript
> // 自动切换语言
> const locale = {
>   'cn': 'zh-CN',
>   'indo': 'id-ID',
>   'mex': 'es-MX'
> }[currentCountry];
> 
> i18n.locale = locale;
> ```
>
> **优势**：
> - ✅ 一套代码，6 个国家
> - ✅ 路由自动拦截，防止误访问
> - ✅ 配置热更新，无需重新部署
> - ✅ 国际化自动化流程

### Q3.3: 状态管理方案是如何设计的？

**回答**：

> **三种方案组合使用**，根据场景选择：
>
> **1. Vuex Store**（全局状态）
> ```javascript
> // 适用场景：全局共享、需要持久化
> store/
> ├── user.js      // 用户信息
> ├── config.js    // 配置中心
> ├── chat.js      // IM 聊天
> ├── ytalk.js     // YTalk 电话
> └── ticket.js    // 工单
> ```
> 
> **2. EventBus**（事件驱动）
> ```javascript
> // 适用场景：跨组件、跨层级通信
> EventBus.$emit('TICKET_CREATED', {ticketId: '12345'});
> EventBus.$on('TICKET_CREATED', this.handleTicketCreated);
> ```
> 
> **3. Provide/Inject**（上下文传递）
> ```javascript
> // 适用场景：父子组件上下文
> provide() {
>   return {
>     bizSource: this.bizSource,
>     bizId: this.bizId
>   };
> }
> ```
>
> **选择标准**：
> - **全局状态** → Vuex（user、config、chat）
> - **临时事件** → EventBus（工单创建、抽屉打开）
> - **业务上下文** → Provide/Inject（bizSource、bizId）
>
> **注意事项**：
> - EventBus 必须在 `beforeDestroy` 清理监听器
> - Provide/Inject 非响应式，需要返回函数
> - Vuex 模块开启 `namespaced`，避免冲突

## 4. 性能优化类

### Q4.1: 首屏加载时间从 4.5s 优化到 1.5s，具体怎么做的？

**回答**：

> **优化前**：
> - 首屏加载 **4.5 秒**
> - Bundle 体积 **3.2MB**
> - FCP **3.2s**，LCP **4.8s**
>
> **优化措施**：
>
> **1. 路由懒加载**（-30%）
> ```javascript
> const routes = [
>   {
>     path: '/ticket',
>     component: () => import(
>       /* webpackChunkName: "ticket" */
>       './views/ticket'
>     )
>   }
> ];
> ```
> - 拆分成 10+ chunk
> - 首屏只加载核心模块
>
> **2. Ant Design Vue 按需引入**（-40%）
> ```javascript
> // 只引入用到的组件
> import {Button, Table, Modal} from 'ant-design-vue';
> ```
> - Bundle 从 3.2MB 降到 1.8MB
>
> **3. 代码分割**（-15%）
> ```javascript
> splitChunks: {
>   cacheGroups: {
>     vendors: {
>       test: /[\\/]node_modules[\\/]/,
>       name: 'vendors'
>     }
>   }
> }
> ```
> - vendors.js 单独缓存
>
> **4. 预加载关键资源**（-10%）
> ```html
> <link rel="preload" href="/js/vendors.js" as="script">
> ```
>
> **5. 图片优化**（-5%）
> - CDN + WebP
> - 懒加载
> - 压缩
>
> **优化后**：
> - 首屏加载 **1.5 秒**（-67%）
> - Bundle 体积 **1.1MB**（-65%）
> - FCP **1.2s**，LCP **1.8s**
>
> **监控**：
> - Sentry 性能监控
> - 每日报表
> - 自动告警（> 2s）

### Q4.2: 长列表性能优化具体怎么做的？

**回答**：

> **问题**：
> - 聊天消息列表 **1000+ 条**
> - 每条消息包含图片、视频、富文本
> - 滚动卡顿，内存占用 **500MB**
>
> **解决方案**：
>
> **1. 虚拟滚动**（核心）
> ```vue
> <RecycleScroller
>   :items="messages"
>   :item-size="100"
>   key-field="id"
>   v-slot="{item}"
> >
>   <ChatMessage :message="item" />
> </RecycleScroller>
> ```
> - 只渲染可见区域 + 缓冲区
> - DOM 节点从 1000+ 降到 **20**
>
> **2. 分页加载**
> ```javascript
> // 首屏只加载 50 条
> async loadMore() {
>   const messages = await ChatAPI.getMessages({
>     page: this.page,
>     pageSize: 50
>   });
>   this.messages.unshift(...messages);
> }
> ```
>
> **3. 图片懒加载**
> ```vue
> <img v-lazy="imageUrl" />
> ```
> - 可见时才加载
>
> **4. 防抖/节流**
> ```javascript
> handleScroll: throttle(function(event) {
>   this.checkLoadMore(event);
> }, 100)
> ```
>
> **5. Web Worker**（大文件处理）
> ```javascript
> // 解析大文件在 Worker 中进行
> const worker = new Worker('parser.worker.js');
> worker.postMessage(file);
> ```
>
> **效果**：
> - DOM 节点：**1000+ → 20**（-98%）
> - 内存占用：**500MB → 80MB**（-84%）
> - 滚动 FPS：**20fps → 60fps**
> - 首屏渲染：**2s → 0.3s**

## 5. 难点挑战类

### Q5.1: 遇到过最大的技术难点是什么？如何解决的？

**回答（STAR 法则）**：

> **Situation（情况）**：
> 项目中 WebSocket 频繁断线，导致消息丢失，用户体验很差。断线原因复杂：网络抖动、服务端重启、负载均衡切换等。
>
> **Task（任务）**：
> 我的任务是设计一套稳定的 WebSocket 重连机制，保证消息可靠性。
>
> **Action（行动）**：
>
> **1. 指数退避重连**
> ```javascript
> // 延迟按 1.5 倍递增：1s -> 1.5s -> 2.25s -> ... -> 30s
> const delay = Math.min(
>   1000 * Math.pow(1.5, attempts),
>   30000
> );
> ```
> - 避免"重连风暴"
> - 给服务端缓冲时间
>
> **2. 消息队列缓存**
> ```javascript
> // 断线期间消息存队列
> if (!isConnected) {
>   messageQueue.push(message);
> }
> 
> // 重连后批量发送
> while (messageQueue.length > 0) {
>   const msg = messageQueue.shift();
>   ws.send(JSON.stringify(msg));
> }
> ```
>
> **3. 心跳机制**
> ```javascript
> // 30 秒发一次心跳
> setInterval(() => {
>   ws.send(JSON.stringify({type: 'PING'}));
> }, 30000);
> 
> // 60 秒未响应，判定连接已死
> setTimeout(() => {
>   if (!receivedPong) {
>     ws.close(); // 主动关闭，触发重连
>   }
> }, 60000);
> ```
>
> **4. 消息确认机制**
> ```javascript
> // 客户端发送消息带 messageId
> send({messageId: uuid(), content: 'Hello'});
> 
> // 服务端返回 ACK
> onMessage((msg) => {
>   if (msg.type === 'ACK') {
>     confirmMessage(msg.messageId);
>   }
> });
> 
> // 5 秒未收到 ACK，自动重发
> setTimeout(() => {
>   if (!isConfirmed(messageId)) {
>     resend(messageId);
>   }
> }, 5000);
> ```
>
> **Result（结果）**：
> - 重连成功率：**80% → 98%**
> - 消息丢失率：**5% → 0.1%**
> - 用户投诉：**每周 10+ → 每月 < 3**
> - 系统可用性：**95% → 99.9%**

### Q5.2: YTalk 跨 Tab 冲突是怎么解决的？

**回答（STAR 法则）**：

> **S**：用户打开多个 Tab，Tab A 正在通话时，Tab B 也能接听来电，导致两个 Tab 争抢麦克风/扬声器资源，通话质量很差。
>
> **T**：需要实现跨 Tab 状态同步，保证同一时刻只有一个 Tab 能通话。
>
> **A**：
>
> **1. Broadcast Channel 同步状态**
> ```javascript
> class YTalkSharedState {
>   constructor() {
>     this.channel = new BroadcastChannel('ytalk-channel');
>     this.tabId = `tab-${Date.now()}`;
>   }
>   
>   // Tab A 接听来电
>   acceptCall(callUuid) {
>     this.channel.postMessage({
>       type: 'CALL_ACCEPTED',
>       callUuid,
>       tabId: this.tabId
>     });
>   }
>   
>   // Tab B 收到广播，禁用通话
>   handleMessage(event) {
>     if (event.data.type === 'CALL_ACCEPTED') {
>       if (event.data.tabId !== this.tabId) {
>         this.disableCallButtons();
>       }
>     }
>   }
> }
> ```
>
> **2. 资源互斥锁**
> ```javascript
> // Tab A 通话中，Tab B 禁用呼出按钮
> computed: {
>   canMakeCall() {
>     return !YTalkSharedState.isInCall;
>   }
> }
> ```
>
> **3. 友好提示**
> ```javascript
> if (!this.canMakeCall) {
>   this.$message.warning('其他标签页正在通话中');
>   return;
> }
> ```
>
> **R**：
> - **0** 跨 Tab 冲突
> - 通话质量稳定
> - 用户体验提升

## 6. 团队协作类

### Q6.1: 如何进行 Code Review？

**回答**：

> **Code Review 流程**：
>
> **1. 提交前自检**
> - ESLint + Prettier 自动格式化
> - 运行单元测试
> - 本地测试验证功能
>
> **2. 创建 Diff**（Phabricator）
> ```bash
> arc diff
> ```
> - 自动触发 Lint 检查
> - 自动触发单元测试
>
> **3. Review 要点**
> - **功能正确性**：逻辑是否正确？边界条件是否考虑？
> - **代码规范**：命名、格式、注释
> - **性能**：是否有性能问题？循环、递归、内存泄漏
> - **安全**：XSS、SQL 注入、CSRF
> - **可维护性**：是否易于理解？是否过度设计？
>
> **4. Review 反馈**
> - **Blocking**：必须修改（逻辑错误、安全问题）
> - **Non-blocking**：建议修改（优化、重构）
> - **Nit**：小问题（命名、格式）
>
> **5. 修改后再次 Review**
> ```bash
> arc diff --update D12345
> ```
>
> **6. 合并代码**
> ```bash
> arc land
> ```
>
> **Review 原则**：
> - ✅ 积极反馈，提出建设性意见
> - ✅ 尊重作者，不要人身攻击
> - ✅ 先看主要问题，再看细节
> - ✅ 给出具体建议和示例代码
