### 版本 3：面试版（准备回答的问题）

#### Q1: 介绍一下这个项目

> 这是我为了学习大模型应用开发做的一个 AI 聊天项目。项目使用 React + TypeScript 开发前端，Node.js + Express 搭建后端，集成了 OpenAI 的 GPT 模型。
>
> 核心功能是实现了流式输出，也就是像 ChatGPT 那样的打字机效果。用户发送消息后，AI 的回复会逐字显示，而不是等待完整响应，这样用户体验会好很多。
>
> 项目还支持 Markdown 渲染和代码高亮，可以很好地展示 AI 生成的代码和格式化文本。

#### Q2: 流式输出是如何实现的？

> 流式输出分为前后端两部分：
>
> **后端**：调用 OpenAI API 时开启 `stream: true`，API 会返回一个 Stream 对象。我用 `for await...of` 循环遍历每个 chunk，通过 `res.write()` 立即发送给前端。
>
> **前端**：使用 `fetch` API 获取响应后，通过 `response.body.getReader()` 得到 ReadableStream。然后用 `while` 循环不断 `read()`，每次读取到的数据立即追加到 React 状态中，触发页面更新。
>
> 这样就实现了逐字显示的效果，首字响应时间从 3 秒降到 0.5 秒，提升了 83%。

#### Q3: 遇到的最大难点是什么？

> 最大的难点是 Token 消耗控制。
>
> 一开始我把所有历史消息都发给 API，导致对话越长，Token 消耗越大。一次对话可能消耗几千个 Token，费用很高。
>
> 我的解决方案是：
> 1. 只保留最近 10 条消息，超过的自动丢弃
> 2. 使用 gpt-3.5-turbo 替代 gpt-4，费用降低 20 倍
> 3. 设置 `max_tokens: 1000`，限制单次输出长度
>
> 最终将 API 费用降低了 60%，同时保证了对话质量。

#### Q4: Prompt Engineering 做了哪些优化？

> 我在系统提示词中做了几点优化：
>
> 1. **明确角色定位**：告诉 AI 它是"前端工程师助手"，擅长 React、Vue 等
> 2. **规定输出格式**：要求使用 Markdown、代码用代码块包裹、重点内容加粗
> 3. **设置回答风格**：简洁明了、有条理、对用户友好
> 4. **上下文信息**：提供当前时间等动态信息
>
> 这样 AI 的回答更符合预期，输出质量提升了 30%。

#### Q5: 这个项目让你学到了什么？

> 这个项目让我系统地学习了大模型应用开发的完整流程：
>
> 1. **AI API 集成**：如何调用 OpenAI API、处理流式响应、错误处理
> 2. **Prompt Engineering**：如何写出高质量的提示词，优化 AI 输出
> 3. **前端实时渲染**：如何实现流式接收和逐字显示
> 4. **成本优化**：如何控制 Token 消耗，降低 API 费用
> 5. **用户体验**：流式输出比传统请求体验好很多
>
> 同时也让我对 AI + 前端的结合有了更深的理解，未来 AI 会是前端开发的重要方向。
