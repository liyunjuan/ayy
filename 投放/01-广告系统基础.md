## 1. 核心概念

### 1.1 基础术语

| 术语 | 英文 | 含义 | 示例 |
|------|------|------|------|
| **曝光** | Impression | 广告被展示的次数 | 用户刷到广告 = 1次曝光 |
| **点击** | Click | 用户点击广告的次数 | 点击广告进入落地页 = 1次点击 |
| **转化** | Conversion | 用户完成目标行为 | 注册/下单/付费 = 1次转化 |
| **CTR** | Click Through Rate | 点击率 = 点击数/曝光数 | 1000曝光100点击 = CTR 10% |
| **CVR** | Conversion Rate | 转化率 = 转化数/点击数 | 100点击10转化 = CVR 10% |
| **ROI** | Return On Investment | 投资回报率 | 花1000赚2000 = ROI 100% |

### 1.2 计费指标

| 指标 | 英文 | 计算公式 | 含义 |
|------|------|----------|------|
| **CPM** | Cost Per Mille | 消耗 / 曝光数 × 1000 | 千次曝光成本 |
| **CPC** | Cost Per Click | 消耗 / 点击数 | 单次点击成本 |
| **CPA** | Cost Per Action | 消耗 / 转化数 | 单次转化成本 |
| **eCPM** | effective CPM | (消耗 / 曝光数) × 1000 | 有效千次曝光成本 |

### 1.3 核心公式

```javascript
// 基础公式
CTR = (点击数 / 曝光数) × 100%
CVR = (转化数 / 点击数) × 100%
ROI = (收入 - 成本) / 成本 × 100%

// 计费公式
CPM = (消耗 / 曝光数) × 1000
CPC = 消耗 / 点击数
CPA = 消耗 / 转化数

// 转化链路
曝光 → 点击 → 转化
1000  → 100   → 10
      (CTR 10%)  (CVR 10%)
```

## 2. 计费模式

### 2.1 CPM - 按曝光计费

**定义**：Cost Per Mille，按千次曝光计费

```javascript
// 案例
曝光数：100,000 次
CPM：10元
消耗 = (100,000 / 1000) × 10 = 1,000元
```

**特点**：
- ✅ 适合品牌曝光
- ✅ 成本可控
- ❌ 不保证点击和转化

**适用场景**：
- 品牌广告（宝马、可口可乐）
- 新品发布
- 活动推广

### 2.2 CPC - 按点击计费

**定义**：Cost Per Click，按点击次数计费

```javascript
// 案例
点击数：1,000 次
CPC：2元
消耗 = 1,000 × 2 = 2,000元
```

**特点**：
- ✅ 按效果付费
- ✅ 风险较低
- ❌ 单价可能较高

**适用场景**：
- 效果广告（电商、游戏）
- 搜索广告
- 信息流广告

### 2.3 CPA - 按转化计费

**定义**：Cost Per Action，按转化行为计费

```javascript
// 案例
转化数：100 次（注册/下单）
CPA：50元
消耗 = 100 × 50 = 5,000元
```

**特点**：
- ✅ 只为结果付费
- ✅ ROI 可控
- ❌ 对投放能力要求高

**适用场景**：
- 电商（下单/付费）
- APP（下载/注册）
- 游戏（付费用户）

### 2.4 CPT - 按时间计费

**定义**：Cost Per Time，按展示时间计费

```javascript
// 案例
投放时长：7天
CPT：10,000元/天
消耗 = 7 × 10,000 = 70,000元
```

**特点**：
- ✅ 固定成本
- ✅ 保证曝光位
- ❌ 价格昂贵

**适用场景**：
- 开屏广告
- 首页焦点图
- 黄金资源位

### 2.5 计费模式对比

| 模式 | 适合广告主 | 风险 | 成本 | 场景 |
|------|-----------|------|------|------|
| **CPM** | 品牌广告主 | 高 | 低 | 品牌曝光 |
| **CPC** | 效果广告主 | 中 | 中 | 引流获客 |
| **CPA** | 效果广告主 | 低 | 高 | 直接转化 |
| **CPT** | 大品牌 | 低 | 高 | 独占资源位 |

## 3. 广告生态

### 3.1 核心角色

```
广告主（Advertiser）
    ↓ 投放广告
DSP（需求方平台）
    ↓ 竞价
Ad Exchange（广告交易平台）
    ↑ 流量
SSP（供给方平台）
    ↑ 提供流量
媒体（Publisher）
```

### 3.2 DSP - 需求方平台

**定义**：Demand-Side Platform，为广告主提供投放服务的平台

**核心功能**：
- 广告创建和管理
- 定向投放
- 自动出价
- 效果监控

**典型平台**：
- 巨量引擎（字节跳动）
- 腾讯广告
- 阿里妈妈
- 百度推广

### 3.3 SSP - 供给方平台

**定义**：Supply-Side Platform，为媒体提供流量变现服务的平台

**核心功能**：
- 流量管理
- 收益优化
- 广告投放控制
- 数据分析

**典型平台**：
- Google AdSense
- 百度联盟
- 腾讯优量汇

### 3.4 DMP - 数据管理平台

**定义**：Data Management Platform，用户数据管理和分析平台

**核心功能**：
- 用户画像
- 人群定向
- Look-alike（相似人群扩展）
- 数据分析

**数据维度**：
```javascript
{
  // 基础属性
  age: 25,
  gender: 'male',
  location: '北京',
  
  // 兴趣标签
  interests: ['科技', '游戏', '旅游'],
  
  // 行为数据
  behaviors: {
    browsing: ['手机', '电脑'],
    purchasing: ['数码产品'],
    searching: ['iPhone']
  },
  
  // 设备信息
  device: {
    type: 'mobile',
    brand: 'iPhone',
    os: 'iOS 17'
  }
}
```

### 3.5 Ad Exchange - 广告交易平台

**定义**：连接 DSP 和 SSP 的实时竞价市场

**工作流程**：
```
1. 用户访问网站/APP
2. SSP 发起广告请求
3. Ad Exchange 组织竞价
4. 多个 DSP 出价
5. 最高出价者获胜
6. 广告展示给用户
7. 记录曝光和消耗

整个流程 < 100ms
```

## 4. 投放流程

### 4.1 完整流程

```
1. 创建广告账户
   ↓
2. 充值预算
   ↓
3. 创建广告计划（Campaign）
   - 设置投放目标（曝光/点击/转化）
   - 设置总预算和投放时间
   ↓
4. 创建广告组（Ad Group）
   - 配置定向条件
   - 设置出价策略
   - 分配预算
   ↓
5. 创建广告创意（Ad Creative）
   - 上传素材（图片/视频）
   - 编写文案
   - 设置落地页
   ↓
6. 提交审核
   - 平台审核（1-24小时）
   - 审核通过/拒绝/修改
   ↓
7. 开始投放
   - 实时竞价
   - 广告展示
   - 数据收集
   ↓
8. 监控和优化
   - 查看数据报表
   - 调整出价
   - 优化创意
   - 调整定向
```

### 4.2 广告层级

```
账户（Account）
  ├── 广告计划1（Campaign）
  │     ├── 广告组1-1（Ad Group）
  │     │     ├── 广告创意1-1-1（Ad Creative）
  │     │     └── 广告创意1-1-2
  │     └── 广告组1-2
  │           └── 广告创意1-2-1
  └── 广告计划2
        └── ...
```

**层级说明**：

| 层级 | 配置内容 | 示例 |
|------|---------|------|
| **账户** | 充值、资质认证 | 企业账户 |
| **广告计划** | 投放目标、总预算、时间 | "双11大促" 预算10万 |
| **广告组** | 定向条件、出价、日预算 | 北京25-35岁男性 CPC 2元 |
| **广告创意** | 素材、文案、落地页 | 商品图片 + 促销文案 |

## 5. 竞价机制

### 5.1 广义第二价格（GSP）

**原理**：最高出价者获胜，但按第二高价 + 0.01元 支付

```javascript
// 竞价示例
const bids = [
  { advertiser: 'A', bid: 10.0, quality: 0.9 },  // 综合得分 9.0
  { advertiser: 'B', bid: 8.0, quality: 1.0 },   // 综合得分 8.0
  { advertiser: 'C', bid: 6.0, quality: 0.8 }    // 综合得分 4.8
]

// 排序后
// A 获胜，实际支付 = (B的综合得分 / A的质量分) + 0.01
//                = (8.0 / 0.9) + 0.01 = 8.89元

// 而不是直接支付 A 的出价 10元
```

**优势**：
- 鼓励真实出价（不用虚高）
- 降低广告主成本
- 提高平台收益

### 5.2 综合排名得分

```javascript
综合得分 = 出价 × 质量分

质量分 = f(
  预估点击率 CTR,    // 权重 40%
  预估转化率 CVR,    // 权重 30%
  广告质量,          // 权重 20%
  落地页体验         // 权重 10%
)
```

**示例**：
```javascript
// 广告 A
出价: 10元
质量分: 0.6
综合得分: 6.0

// 广告 B
出价: 8元
质量分: 0.9
综合得分: 7.2  // B 获胜！
```

### 5.3 实时竞价（RTB）

**流程**（整个过程 < 100ms）：

```javascript
// 1. 用户触发广告请求（10ms）
request = {
  userId: 'user123',
  page: 'homepage',
  adSlot: 'banner-top'
}

// 2. 召回候选广告（30ms）
const candidates = await recallAds({
  location: '北京',
  age: 25,
  gender: 'male',
  interests: ['科技', '游戏']
})
// 召回 100 个候选广告

// 3. 粗排（10ms）
const coarseRanked = coarseRank(candidates)
// 筛选出 20 个广告

// 4. 精排（30ms）
const fineRanked = fineRank(coarseRanked)
// 计算综合得分，排序

// 5. 竞价和扣费（10ms）
const winner = fineRanked[0]
const actualCost = calculateCost(fineRanked)

// 6. 返回广告（10ms）
return {
  ad: winner,
  cost: actualCost
}
```

### 6.1 定向维度

```javascript
const targeting = {
  // 1. 基础定向

  interests: [
    '科技数码',
    '游戏娱乐',
    '汽车',
    '旅游'
  ],
  
  // 3. 行为定向

    browsing: ['浏览过 iPhone'],                 // 浏览行为
    searching: ['搜索过 "手机"'],                // 搜索行为
    purchasing: ['购买过数码产品']               // 购买行为
  },
  
  // 4. 设备定向
  device: {
    type: ['mobile'],                            // 设备类型
    os: ['iOS', 'Android'],                      // 操作系统
    brand: ['Apple', 'Huawei'],                  // 设备品牌
    network: ['WiFi', '4G', '5G']                // 网络环境
  },
  
  // 5. 场景定向
  context: {
    time: ['09:00-22:00'],                       // 时间段
    weather: ['晴天', '雨天'],                   // 天气
    location: ['商场', '地铁站']                 // 地理位置
  },
  
  // 6. 人群包定向
  audience: {
    retargeting: ['访问过官网的用户'],           // 重定向
    lookalike: ['种子用户的相似人群'],           // 相似扩展
    custom: ['自定义上传的用户ID']              // 自定义人群
  }
}
```

### 6.2 人群包

**1. 重定向人群（Retargeting）**

```javascript
// 场景：用户访问过商品页但没下单
const retargetingAudience = {

}
```

**2. Look-alike 相似人群**


## 8. 典型案例

### 案例1：电商品牌推广

```javascript
{
  advertiser: '某手机品牌',
  goal: '新品发布推广',
  
  // 策略
  strategy: {
    stage1: {                         // 第1周：品牌曝光
      target: 'impression',
      bidType: 'CPM',
      targeting: '广泛定向',
      budget: 50000,
      expectedImpression: 5000000     // 500万曝光
    },
    stage2: {                         // 第2周：引流获客
      target: 'click',
      bidType: 'CPC',
      targeting: '兴趣定向',
      budget: 100000,
      expectedClick: 50000            // 5万点击
    },
    stage3: {                         // 第3-4周：转化收割
      target: 'conversion',
      bidType: 'oCPM',
      targeting: '重定向+相似人群',
      budget: 150000,
      expectedConversion: 3000        // 3000单
    }
  },
  
  // 结果
  result: {
    totalCost: 300000,
    impressions: 5500000,
    clicks: 55000,
    conversions: 3300,
    revenue: 9900000,                 // 客单价 3000元
    roi: 3200                         // ROI 3200%
  }
}
```

## 9. 面试常见问题

### Q1: CPM 和 CPC 如何选择?

**回答思路**：
```
1. 看目标
   - 品牌曝光 → CPM
   - 效果转化 → CPC/CPA

2. 看预算
   - 预算充足 → CPA（效果最好）
   - 预算有限 → CPC（风险适中）
   - 预算紧张 → CPM（成本最低）

3. 看行业
   - 电商/游戏 → CPC/CPA
   - 品牌广告 → CPM
   - APP下载 → CPA

4. 看阶段
   - 冷启动期 → CPM（积累数据）
   - 成长期 → CPC（扩大流量）
   - 成熟期 → CPA（优化成本）
```

### Q2: 什么是 oCPM?

**回答**：
```
oCPM = optimized CPM（优化后的 CPM）

原理：
1. 按 CPM 计费（按曝光）
2. 但优化目标是转化
3. 系统自动调整出价，优先投放给高转化人群

优势：
- 兼顾流量和转化
- 系统智能优化
- 效果好于普通 CPM

适用：
- 有一定转化数据积累
- 追求转化效果
- 预算充足
```

### Q3: 如何提升广告 ROI?

**回答思路**：
```
1. 定向优化
   - 分析高转化人群特征
   - 排除低效人群
   - Look-alike 扩展

2. 创意优化
   - A/B 测试文案和素材
   - 优化落地页转化率
   - 提升视觉吸引力

3. 出价优化
   - 高峰时段提高出价
   - 低峰时段降低出价
   - 使用智能出价

4. 链路优化
   - 缩短转化路径
   - 提升页面加载速度
   - 优化支付流程

5. 数据分析
   - 找出高 ROI 时段/地域/人群
   - 归因分析，优化渠道组合
   - 持续迭代优化
```

### Q4: 重定向（Retargeting）的原理?

**回答**：
```
原理：
1. 用户访问网站/APP，打上标签
2. 用户离开后，在其他平台看到广告
3. 引导用户回来完成转化

技术实现：
- Cookie（Web）
- 设备ID（APP）
- 用户ID（登录用户）

优势：
- 针对高意向用户
- 转化率高
- ROI 高

场景：
- 加购未下单用户
- 浏览未注册用户
- 试用未付费用户
```
