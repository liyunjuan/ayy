## 1. 缓存概述

### 1.1 什么是 HTTP 缓存？

**定义**：将服务器响应的资源副本存储在客户端或中间代理，下次请求时直接使用副本，无需再次请求服务器。

**目的**：
- ✅ 减少网络流量
- ✅ 降低服务器负载
- ✅ 加快页面加载速度
- ✅ 提升用户体验

---

### 1.2 缓存位置

```
请求路径：浏览器 → Service Worker → Memory Cache → Disk Cache → HTTP 缓存 → 服务器

┌─────────────────────────────────────────────────────┐
│  浏览器缓存层级                                      │
├─────────────────────────────────────────────────────┤
│  1. Service Worker Cache                            │
│     - 开发者完全控制                                 │
│     - 离线应用                                       │
├─────────────────────────────────────────────────────┤
│  2. Memory Cache（内存缓存）                        │
│     - 速度最快                                       │
│     - 容量小                                         │
│     - 关闭标签页即清除                               │
├─────────────────────────────────────────────────────┤
│  3. Disk Cache（磁盘缓存）                          │
│     - 速度较快                                       │
│     - 容量大                                         │
│     - 持久化存储                                     │
├─────────────────────────────────────────────────────┤
│  4. Push Cache（HTTP/2 推送缓存）                   │
│     - HTTP/2 特性                                    │
│     - 会话级别                                       │
└─────────────────────────────────────────────────────┘
```

**缓存优先级**：
```
Service Worker → Memory Cache → Disk Cache → 网络请求
```

---

### 1.3 缓存的类型

```
HTTP 缓存
├── 私有缓存（Private Cache）
│   └── 浏览器缓存（只能单个用户使用）
└── 共享缓存（Shared Cache）
    ├── 代理缓存（Proxy Cache）
    └── CDN 缓存（全球分发）
```

### 2.1 核心问题：谁写缓存？

**通过响应头控制缓存行为**：

```http
[图片数据]
```

### 2.4 客户端的职责

```javascript
// 浏览器内部处理流程（伪代码）

class BrowserCache {
  async fetch(url, options) {
    // 1. 查找缓存
    const cached = this.getFromCache(url);
    
    if (cached) {
      // 2. 检查强缓存是否有效
      if (this.isFreshCache(cached)) {
        console.log('200 (from disk cache)');
        return cached.response;
      }
      
      // 3. 缓存过期，发起协商缓存请求
      const headers = {
        'If-None-Match': cached.etag,
        'If-Modified-Since': cached.lastModified
      };
      
      const response = await this.networkRequest(url, { headers });
      
      if (response.status === 304) {
        // 4. 服务器返回 304，使用缓存
        console.log('304 Not Modified');
        this.updateCacheTimestamp(url);
        return cached.response;
      }
      
      // 5. 服务器返回新内容，更新缓存
      this.saveToCache(url, response);
      return response;
    }
    
    // 6. 缓存不存在，发起网络请求
    const response = await this.networkRequest(url);
    
    // 7. 根据响应头决定是否缓存
    if (this.shouldCache(response)) {
      this.saveToCache(url, response);
    }
    
    return response;
  }
  
  isFreshCache(cached) {
    const now = Date.now();
    const age = now - cached.timestamp;
    const maxAge = cached.maxAge * 1000;
    return age < maxAge;
  }
  
  shouldCache(response) {
    const cacheControl = response.headers['cache-control'];
    return !cacheControl.includes('no-store');
  }
}
```

## 3. 强缓存

### 3.1 什么是强缓存？

**定义**：客户端直接从缓存读取资源，**不发送 HTTP 请求**到服务器。

**特点**：
- ✅ 速度最快（无网络开销）
- ✅ 节省带宽
- ❌ 无法实时更新（缓存期内）

**状态码**：
- `200 OK (from memory cache)`：从内存读取
- `200 OK (from disk cache)`：从磁盘读取

---

### 3.2 强缓存控制头

#### Cache-Control（推荐）

```http
Cache-Control: public, max-age=31536000
```

**指令详解**：

| 指令 | 含义 | 示例 |
|------|------|------|
| **max-age=\<seconds\>** | 缓存有效期（秒） | `max-age=3600`（1 小时）|
| **s-maxage=\<seconds\>** | 共享缓存有效期（覆盖 max-age）| `s-maxage=86400`（CDN 缓存 1 天）|
| **public** | 可被任何缓存存储（CDN、代理）| `public` |
| **private** | 只能被浏览器缓存（不能被 CDN 缓存）| `private` |
| **no-cache** | 可以缓存，但每次使用前必须验证 | `no-cache` |
| **no-store** | 禁止缓存（敏感数据）| `no-store` |
| **must-revalidate** | 缓存过期后必须验证 | `must-revalidate` |
| **immutable** | 资源不会变化（推荐用于带哈希的静态资源）| `immutable` |

---

#### 常见组合

```http
# 1. 不缓存（敏感数据）
Cache-Control: no-store, no-cache, must-revalidate

# 2. 每次验证（HTML 页面）
Cache-Control: no-cache

# 3. 短期缓存（API 数据）
Cache-Control: private, max-age=300

# 4. 长期缓存（带哈希的静态资源）
Cache-Control: public, max-age=31536000, immutable

# 5. CDN 缓存（静态资源）
Cache-Control: public, max-age=3600, s-maxage=86400
```

---

#### Expires（已过时）

```http
Expires: Mon, 01 Jan 2027 00:00:00 GMT
```

**问题**：
- 依赖客户端时间（可能不准确）
- 时区问题
- 优先级低于 `Cache-Control`

**现状**：仅用于兼容旧浏览器（HTTP/1.0）

---

### 3.3 强缓存示例

#### 服务器端（Node.js/Express）

```javascript
const express = require('express');
const path = require('path');

const app = express();

// 静态资源：长期缓存
app.use('/static', express.static('public', {
  maxAge: '1y', // 1 年
  immutable: true,
  setHeaders: (res, filePath) => {
    // 为带哈希的文件设置长期缓存
    if (filePath.match(/\.[a-f0-9]{8}\.(js|css|jpg|png)$/)) {
      res.setHeader('Cache-Control', 'public, max-age=31536000, immutable');
    }
  }
}));

// HTML 文件：不缓存
app.get('/', (req, res) => {
  res.set({
    'Cache-Control': 'no-cache, no-store, must-revalidate',
    'Pragma': 'no-cache',
    'Expires': '0'
  });
  res.sendFile(path.join(__dirname, 'index.html'));
});

// API 接口：短期缓存
app.get('/api/config', (req, res) => {
  res.set({
    'Cache-Control': 'private, max-age=300' // 5 分钟
  });
  res.json({ version: '1.0.0' });
});

app.listen(3000);
```

### 3.4 强缓存判断流程

```javascript
function shouldUseStrongCache(cachedResource) {
  const cacheControl = parseCacheControl(cachedResource.headers['cache-control']);
  
  // 1. no-store：禁止缓存
  if (cacheControl.noStore) {
    return false;
  }
  
  // 2. no-cache：跳过强缓存，进入协商缓存
  if (cacheControl.noCache) {
    return false;
  }
  
  // 3. 检查 max-age
  if (cacheControl.maxAge !== undefined) {
    const age = (Date.now() - cachedResource.timestamp) / 1000;
    if (age < cacheControl.maxAge) {
      return true; // 强缓存有效
    }
  }
  
  // 4. 检查 Expires（兼容旧版）
  const expires = new Date(cachedResource.headers['expires']);
  if (expires > new Date()) {
    return true; // 强缓存有效
  }
  
  // 5. 强缓存过期
  return false;
}
```

## 4. 协商缓存

### 4.1 什么是协商缓存？

**定义**：缓存过期后，客户端向服务器发送请求，**服务器判断**资源是否需要更新。

**特点**：
- ✅ 有网络请求（带验证标识）
- ✅ 如果资源未变化，返回 304，节省数据传输
- ✅ 如果资源已变化，返回 200 + 新数据

**状态码**：
- `304 Not Modified`：资源未变化，使用缓存
- `200 OK`：资源已变化，返回新内容

---

### 4.2 协商缓存标识

#### ETag / If-None-Match（推荐）

**原理**：服务器为每个资源生成唯一标识（哈希值）

```http
# 首次响应
HTTP/1.1 200 OK
ETag: "abc123def456"      ← 服务器生成资源标识
Content-Length: 12345

[资源内容]
```

```http
# 后续请求（缓存过期）
GET /logo.png HTTP/1.1
If-None-Match: "abc123def456"  ← 客户端带上 ETag

# 服务器响应（资源未变化）
HTTP/1.1 304 Not Modified
ETag: "abc123def456"
Content-Length: 0

# 或（资源已变化）
HTTP/1.1 200 OK
ETag: "xyz789ghi012"      ← 新的 ETag
Content-Length: 23456

[新的资源内容]
```

**ETag 生成方式**：
```javascript
// 方式 1：文件内容哈希（推荐）
const crypto = require('crypto');
const fs = require('fs');

function generateETag(filePath) {
  const content = fs.readFileSync(filePath);
  const hash = crypto.createHash('md5').update(content).digest('hex');
  return `"${hash}"`;
}

// 方式 2：文件修改时间 + 大小
function generateWeakETag(filePath) {
  const stats = fs.statSync(filePath);
  return `W/"${stats.mtime.getTime()}-${stats.size}"`;
}
```

---

#### Last-Modified / If-Modified-Since

**原理**：基于文件最后修改时间

```http
# 首次响应
HTTP/1.1 200 OK
Last-Modified: Mon, 01 Jan 2026 10:30:00 GMT  ← 最后修改时间
Content-Length: 12345

[资源内容]
```

```http
# 后续请求（缓存过期）
GET /logo.png HTTP/1.1
If-Modified-Since: Mon, 01 Jan 2026 10:30:00 GMT  ← 客户端带上时间

# 服务器响应（未修改）
HTTP/1.1 304 Not Modified

# 或（已修改）
HTTP/1.1 200 OK
Last-Modified: Tue, 02 Jan 2026 14:20:00 GMT  ← 新的修改时间
Content-Length: 23456

[新的资源内容]
```

**缺点**：
- 精度只到秒（1 秒内的修改无法识别）
- 文件修改时间可能被篡改
- 内容未变但时间变了（如重新部署）

---

### 4.3 ETag vs Last-Modified

| 特性 | ETag | Last-Modified |
|------|------|---------------|
| **精度** | 高（内容变化即改变）| 低（秒级）|
| **准确性** | 高（内容相同则相同）| 低（时间可能不准确）|
| **性能** | 低（需计算哈希）| 高（读文件属性）|
| **优先级** | 高 | 低 |
| **适用场景** | 静态资源（JS/CSS/图片）| 大文件、不常变化的资源 |

**同时使用时的优先级**：
```
If-None-Match（ETag） > If-Modified-Since（Last-Modified）
```

### 4.4 协商缓存实现

#### 服务器端（Node.js）

```javascript
const express = require('express');
const crypto = require('crypto');
const fs = require('fs');
const path = require('path');

const app = express();

app.get('/logo.png', (req, res) => {
  const filePath = path.join(__dirname, 'public/logo.png');
  
  // 1. 生成 ETag
  const content = fs.readFileSync(filePath);
  const etag = crypto.createHash('md5').update(content).digest('hex');
  const etagWithQuotes = `"${etag}"`;
  
  // 2. 获取 Last-Modified
  const stats = fs.statSync(filePath);
  const lastModified = stats.mtime.toUTCString();
  
  // 3. 检查 If-None-Match（ETag）
  const clientETag = req.headers['if-none-match'];
  if (clientETag === etagWithQuotes) {
    // ETag 匹配，资源未变化
    res.status(304).end();
    return;
  }
  
  // 4. 检查 If-Modified-Since（Last-Modified）
  const clientModified = req.headers['if-modified-since'];
  if (clientModified && new Date(clientModified) >= stats.mtime) {
    // 时间未变化，资源未变化
    res.status(304).end();
    return;
  }
  
  // 5. 资源已变化，返回新内容
  res.set({
    'Cache-Control': 'public, max-age=3600', // 1 小时强缓存
    'ETag': etagWithQuotes,
    'Last-Modified': lastModified,
    'Content-Type': 'image/png'
  });
  
  res.sendFile(filePath);
});

app.listen(3000);
```

```nginx
    }
}
```

## 5. 缓存响应头详解

### 5.1 Cache-Control 完整指令

```http
Cache-Control: <directive1>, <directive2>, ...
```

| 指令 | 类型 | 说明 | 示例场景 |
|------|------|------|----------|
| **max-age=\<seconds\>** | 缓存时长 | 资源最大缓存时间 | `max-age=3600` |
| **s-maxage=\<seconds\>** | 缓存时长 | 共享缓存（CDN）最大缓存时间 | `s-maxage=86400` |
| **public** | 可缓存性 | 任何缓存都可存储 | 公共资源（CSS/JS）|
| **private** | 可缓存性 | 只能被浏览器缓存 | 用户私人数据 |
| **no-cache** | 重验证 | 可缓存，但使用前必须验证 | HTML 页面 |
| **no-store** | 禁止缓存 | 完全禁止缓存 | 敏感数据（密码）|
| **must-revalidate** | 重验证 | 过期后必须验证，不能使用过期缓存 | 重要文档 |
| **proxy-revalidate** | 重验证 | 共享缓存必须验证 | CDN 资源 |
| **immutable** | 不可变 | 资源永不变化（强缓存期内）| 带哈希的静态资源 |
| **no-transform** | 完整性 | 禁止代理修改内容（如压缩）| 已压缩的资源 |
| **stale-while-revalidate=\<seconds\>** | 容错 | 过期后仍可使用，同时后台验证 | 用户体验优化 |
| **stale-if-error=\<seconds\>** | 容错 | 错误时使用过期缓存 | 容错处理 |

---

### 5.2 实用组合示例

#### HTML 页面（不缓存）

```http
Cache-Control: no-cache, no-store, must-revalidate
Pragma: no-cache
Expires: 0
```

**理由**：
- HTML 是入口文件，需实时更新
- `no-cache`：兼容 HTTP/1.1
- `Pragma: no-cache`：兼容 HTTP/1.0
- `Expires: 0`：兼容旧浏览器

---

#### API 数据（短期缓存）

```http
Cache-Control: private, max-age=300
```

**理由**：
- `private`：用户数据，不能被 CDN 缓存
- `max-age=300`：5 分钟内无需重新请求

---

#### 静态资源（长期缓存）

```http
# 不带哈希
Cache-Control: public, max-age=3600

# 带哈希（推荐）
Cache-Control: public, max-age=31536000, immutable
```

**理由**：
- `public`：可被 CDN 缓存
- `immutable`：告诉浏览器资源永不变化，即使刷新页面也不验证

---

#### CDN 分层缓存

```http
Cache-Control: public, max-age=3600, s-maxage=86400
```

**效果**：
- 浏览器缓存 1 小时
- CDN 缓存 1 天
- 用户可能拿到较新的版本，CDN 仍缓存旧版本

---

#### 容错缓存

```http
Cache-Control: max-age=600, stale-while-revalidate=86400, stale-if-error=259200
```

**效果**：
- 正常情况：10 分钟缓存
- 缓存过期：后台异步验证，先返回旧缓存（1 天内）
- 服务器错误：使用旧缓存（3 天内）

---

### 5.3 Vary 头

**作用**：根据请求头的不同值，缓存不同的响应版本

```http
Vary: Accept-Encoding
```

**场景**：
```
请求 1：Accept-Encoding: gzip
响应 1：gzip 压缩版本 → 缓存 Key: /logo.png?gzip

请求 2：Accept-Encoding: br
响应 2：brotli 压缩版本 → 缓存 Key: /logo.png?br

请求 3：Accept-Encoding: identity
响应 3：未压缩版本 → 缓存 Key: /logo.png?identity
```

**常见用法**：
```http
# 根据压缩算法缓存
Vary: Accept-Encoding

# 根据语言缓存
Vary: Accept-Language

# 根据设备类型缓存
Vary: User-Agent

# 组合
Vary: Accept-Encoding, Accept-Language
```

### 6.4 Service Worker 缓存

```javascript
// sw.js - Service Worker 脚本

const CACHE_NAME = 'my-app-v1';
const URLS_TO_CACHE = [
  '/',
  '/static/css/main.css',
  '/static/js/main.js',
  '/static/images/logo.png'
];

// 安装时缓存资源
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME).then((cache) => {
      return cache.addAll(URLS_TO_CACHE);
    })
  );
});

// 拦截请求
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.match(event.request).then((response) => {
      // 缓存命中
      if (response) {
        return response;
      }
      
      // 缓存未命中，发起网络请求
      return fetch(event.request).then((response) => {
        // 检查是否有效响应
        if (!response || response.status !== 200 || response.type !== 'basic') {
          return response;
        }
        
        // 克隆响应（响应流只能消费一次）
        const responseToCache = response.clone();
        
        // 缓存响应
        caches.open(CACHE_NAME).then((cache) => {
          cache.put(event.request, responseToCache);
        });
        
        return response;
      });
    })
  );
});

// 激活时清理旧缓存
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((cacheNames) => {
      return Promise.all(
        cacheNames.map((cacheName) => {
          if (cacheName !== CACHE_NAME) {
            return caches.delete(cacheName);
          }
        })
      );
    })
  );
});
```

### 6.5 移动端缓存优化

```javascript
// 判断网络状况
function getNetworkType() {
  const connection = navigator.connection || 
                     navigator.mozConnection || 
                     navigator.webkitConnection;
  
  if (!connection) {
    return 'unknown';
  }
  
  return connection.effectiveType; // 4g, 3g, 2g, slow-2g
}

// 根据网络状况调整缓存策略
function fetchWithCache(url) {
  const networkType = getNetworkType();
  
  if (networkType === '4g') {
    // 4G：优先网络，后台更新缓存
    return fetch(url).then(response => {
      caches.open('dynamic-cache').then(cache => {
        cache.put(url, response.clone());
      });
      return response;
    });
  } else {
    // 2G/3G：优先缓存，后台更新
    return caches.match(url).then(response => {
      if (response) {
        // 后台更新缓存
        fetch(url).then(newResponse => {
          caches.open('dynamic-cache').then(cache => {
            cache.put(url, newResponse);
          });
        });
        return response;
      }
      return fetch(url);
    });
  }
}
```

### 7.4 前端缓存监控

```javascript
// 监控缓存命中率
class CacheMonitor {
  constructor() {
    this.stats = {
      memory: 0,
      disk: 0,
      network: 0
    };
    
    this.monitor();
  }
  
  monitor() {
    if (!window.PerformanceObserver) return;
    
    const observer = new PerformanceObserver((list) => {
      for (const entry of list.getEntries()) {
        if (entry.entryType === 'resource') {
          this.recordCache(entry);
        }
      }
    });
    
    observer.observe({ entryTypes: ['resource'] });
  }
  
  recordCache(entry) {
    const transferSize = entry.transferSize;
    const encodedBodySize = entry.encodedBodySize;
    
    if (transferSize === 0 && encodedBodySize > 0) {
      // 从缓存读取
      if (entry.duration < 5) {
        this.stats.memory++;
        console.log(`[Memory Cache] ${entry.name}`);
      } else {
        this.stats.disk++;
        console.log(`[Disk Cache] ${entry.name}`);
      }
    } else {
      // 网络请求
      this.stats.network++;
      console.log(`[Network] ${entry.name} (${transferSize} bytes)`);
    }
  }
  
  getStats() {
    const total = this.stats.memory + this.stats.disk + this.stats.network;
    return {
      ...this.stats,
      total,
      hitRate: ((this.stats.memory + this.stats.disk) / total * 100).toFixed(2) + '%'
    };
  }
}

// 使用
const monitor = new CacheMonitor();

// 页面加载完成后查看统计
window.addEventListener('load', () => {
  setTimeout(() => {
    console.log('缓存统计:', monitor.getStats());
  }, 2000);
});
```

## 8. 常见问题

### 8.1 为什么刷新页面会重新请求？

**原因**：不同的刷新方式，缓存行为不同

| 操作 | 强缓存 | 协商缓存 |
|------|--------|---------|
| **地址栏回车** | ✓ | ✓ |
| **链接跳转** | ✓ | ✓ |
| **前进/后退** | ✓ | ✓ |
| **F5 / Ctrl+R（普通刷新）** | ✗ | ✓ |
| **Ctrl+F5 / Ctrl+Shift+R（强制刷新）** | ✗ | ✗ |

**解释**：
- 普通刷新：跳过强缓存，但保留协商缓存
- 强制刷新：绕过所有缓存，直接请求服务器

3. **CDN 缓存**

### 8.4 为什么 ETag 有时候以 W/ 开头？

**弱 ETag（Weak ETag）**：

```http
ETag: W/"abc123"
```

**特点**：
- 允许语义相同但字节不同的资源使用相同 ETag
- 例如：Gzip 压缩前后的文件
- 服务器认为这些变化不重要

**强 ETag（Strong ETag）**：

```http
ETag: "abc123"
```

**特点**：
- 字节级别的相同
- 任何变化都会导致 ETag 改变

**特点**：
- 低优先级
- 不阻塞当前页面

## 9. 面试高频问答

### Q1: 浏览器缓存机制是什么？

**答案**：

浏览器缓存机制分为**强缓存**和**协商缓存**两种：

**强缓存**：
- 浏览器直接从本地缓存读取资源，**不发送请求**到服务器
- 通过 `Cache-Control` 和 `Expires` 控制
- 状态码：`200 (from memory/disk cache)`

**协商缓存**：
- 缓存过期后，浏览器发送请求询问服务器资源是否有更新
- 通过 `ETag/If-None-Match` 和 `Last-Modified/If-Modified-Since` 实现
- 未变化返回 `304 Not Modified`，已变化返回 `200 + 新数据`

**执行流程**：
```
1. 检查缓存是否存在
2. 存在 → 检查是否过期
3. 未过期 → 强缓存，直接使用
4. 已过期 → 协商缓存，询问服务器
5. 服务器返回 304 → 使用缓存
6. 服务器返回 200 → 使用新数据
```

---

### Q2: 强缓存和协商缓存的区别？

| 特性 | 强缓存 | 协商缓存 |
|------|--------|---------|
| **是否发请求** | 否 | 是 |
| **状态码** | 200 (from cache) | 304 Not Modified |
| **速度** | 最快（无网络开销）| 较快（有网络但无数据传输）|
| **控制头** | Cache-Control, Expires | ETag, Last-Modified |
| **适用场景** | 不常变化的资源 | 可能更新的资源 |

---

### Q3: Cache-Control 的常用指令有哪些？

**可缓存性**：
- `public`：任何缓存都可存储（CDN、代理、浏览器）
- `private`：只能被浏览器缓存
- `no-cache`：可以缓存，但使用前必须验证
- `no-store`：完全禁止缓存

**缓存时长**：
- `max-age=<seconds>`：缓存有效期
- `s-maxage=<seconds>`：共享缓存有效期（覆盖 max-age）

**重验证**：
- `must-revalidate`：过期后必须验证，不能使用过期缓存

**不可变**：
- `immutable`：资源永不变化（强缓存期内）

---

### Q4: ETag 和 Last-Modified 有什么区别？优先级如何？

| 特性 | ETag | Last-Modified |
|------|------|---------------|
| **精度** | 高（内容哈希）| 低（秒级时间）|
| **准确性** | 高（内容相同则相同）| 低（时间可能不准确）|
| **性能** | 低（需计算哈希）| 高（读文件属性）|
| **优先级** | **高** | 低 |

**优先级规则**：
- 如果 `If-None-Match` 和 `If-Modified-Since` 同时存在
- 服务器**优先检查 ETag**
- ETag 匹配即返回 304，忽略 Last-Modified

---

### Q5: 如何设置不缓存？

### Q7: 为什么要使用 immutable？

**问题**：用户点击刷新（F5），浏览器会跳过强缓存，发送协商缓存请求

```
没有 immutable：
用户刷新 → 发送请求（If-None-Match）→ 304 → 使用缓存
（有网络请求，虽然没传输数据，但有延迟）

有 immutable：
用户刷新 → 直接使用缓存（即使点击刷新）
（零网络请求，零延迟）
```

**使用场景**：
```http
# 带哈希的静态资源（永不变化）
Cache-Control: public, max-age=31536000, immutable
```

**效果**：
- 告诉浏览器：即使用户刷新页面，也不要验证这个资源
- 减少不必要的 304 请求

### Q8: Service Worker 缓存和 HTTP 缓存的区别？

| 特性 | Service Worker | HTTP 缓存 |
|------|----------------|-----------|
| **控制权** | 开发者完全控制 | 浏览器自动处理 |
| **灵活性** | 高（可自定义策略）| 低（受响应头限制）|
| **离线能力** | 支持 | 不支持 |
| **缓存位置** | 独立的 Cache Storage | 浏览器缓存 |
| **优先级** | **高**（先于 HTTP 缓存）| 低 |
| **复杂度** | 高（需编写 SW 脚本）| 低（配置响应头）|

**使用建议**：
- **HTTP 缓存**：基础缓存策略（必须）
- **Service Worker**：高级功能（离线、推送、后台同步）

### Q9: 如何监控缓存命中率？

```javascript
// 方式 1：Performance API
const resources = performance.getEntriesByType('resource');

let memoryCache = 0;
let diskCache = 0;
let network = 0;

resources.forEach((entry) => {
  if (entry.transferSize === 0 && entry.encodedBodySize > 0) {
    // 从缓存读取
    if (entry.duration < 5) {
      memoryCache++;
    } else {
      diskCache++;
    }
  } else {
    // 网络请求
    network++;
  }
});

console.log({
  memory: memoryCache,
  disk: diskCache,
  network: network,
  hitRate: ((memoryCache + diskCache) / resources.length * 100).toFixed(2) + '%'
});
```

```javascript
// 方式 2：Chrome DevTools Protocol
chrome.devtools.network.getHAR((har) => {
  const entries = har.entries;
  const cached = entries.filter(e => e.cache.beforeRequest);
  console.log(`缓存命中率: ${cached.length / entries.length * 100}%`);
});
```

### Q10: CDN 缓存和浏览器缓存的关系？

**请求链路**：
```
浏览器 → 浏览器缓存 → CDN 边缘节点 → CDN 缓存 → 源服务器
```

**缓存层级**：
```
┌─────────────────────────────────────────────┐
│  用户 A（北京）                             │
│  └─ 浏览器缓存 1 小时                       │
│     └─ CDN 北京节点缓存 1 天                │
├─────────────────────────────────────────────┤
│  用户 B（上海）                             │
│  └─ 浏览器缓存 1 小时                       │
│     └─ CDN 上海节点缓存 1 天                │
├─────────────────────────────────────────────┤
│  源服务器（深圳）                           │
└─────────────────────────────────────────────┘
```

**配置方式**：
```http
# 浏览器缓存 1 小时，CDN 缓存 1 天
Cache-Control: public, max-age=3600, s-maxage=86400
```

**更新策略**：
```
1. 更新源服务器文件
2. CDN 缓存未过期 → 用户仍看到旧版本
3. 解决：
   - 方式 1：文件名哈希（推荐）
   - 方式 2：手动清除 CDN 缓存
```

## 10. 总结

### 10.1 核心要点

| 知识点 | 要点 |
|-------|------|
| **缓存职责** | 服务器制定策略（响应头），客户端执行策略（存储、读取）|
| **强缓存** | 浏览器独立决定，不发请求，状态码 200 (from cache) |
| **协商缓存** | 浏览器询问服务器，服务器决定，状态码 304 或 200 |
| **Cache-Control** | 最重要的缓存控制头，优先级高于 Expires |
| **ETag** | 内容哈希，精度高，优先级高于 Last-Modified |
| **文件名哈希** | 解决缓存更新问题的最佳方案 |
| **immutable** | 带哈希资源的必备指令，避免不必要的 304 请求 |

### 10.2 最佳实践速查表

```
资源类型          |  Cache-Control 配置
──────────────────┼────────────────────────────────────
HTML 文件         │  no-cache, no-store, must-revalidate
CSS/JS (带哈希)   │  public, max-age=31536000, immutable
CSS/JS (不带哈希) │  public, max-age=3600
图片/字体 (带哈希) │  public, max-age=31536000, immutable
图片/字体 (常用)  │  public, max-age=2592000
API 数据          │  private, max-age=60
Service Worker    │  no-cache, no-store
```
