## 1. Nginx 基础

### 1.1 什么是 Nginx？

**Nginx**：高性能的 HTTP 和反向代理 Web 服务器

**特点**：
- ✅ 高性能、高并发（事件驱动架构）
- ✅ 占用资源少（单进程处理数万并发）
- ✅ 稳定性好
- ✅ 功能丰富（反向代理、负载均衡、缓存）
- ✅ 配置灵活

**对比 Apache**：

| 特性 | Nginx | Apache |
|------|-------|--------|
| **架构** | 事件驱动 | 进程/线程驱动 |
| **并发性能** | 高（数万）| 中（数千）|
| **内存占用** | 低 | 高 |
| **静态文件** | 快 | 慢 |
| **动态内容** | 需要代理 | 内置支持 |
| **配置** | 简洁 | 复杂 |

---

### 1.2 Nginx 架构

```
┌─────────────────────────────────────────┐
│           Master Process                │
│  - 读取配置                             │
│  - 管理 Worker 进程                     │
│  - 处理信号                             │
└────────────┬────────────────────────────┘
             │
    ┌────────┴────────┐
    ▼                 ▼
┌─────────┐      ┌─────────┐
│ Worker 1│      │ Worker 2│  ... Worker N
│ - 处理请求 │      │ - 处理请求 │
│ - 事件驱动 │      │ - 事件驱动 │
└─────────┘      └─────────┘
```

**Master-Worker 模型**：
- **Master 进程**：管理、配置、信号处理
- **Worker 进程**：处理客户端请求
- **优势**：热重启、平滑升级

---

### 1.3 事件驱动架构

**传统 Web 服务器（Apache）**：
```
每个连接 → 一个进程/线程
1000 个连接 → 1000 个进程/线程
内存占用：1000 × 10MB = 10GB
```

**Nginx（事件驱动）**：
```
1 个 Worker 进程 → 处理数万连接
1000 个连接 → 1 个进程
内存占用：10MB
```

**核心机制**：
- **epoll**（Linux）/ kqueue（FreeBSD）
- **异步非阻塞 I/O**
- **事件循环**

## 3. 配置文件详解

### 3.1 配置文件结构

```nginx
# 全局块
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log;
pid /run/nginx.pid;

# events 块
events {
    worker_connections 1024;
    use epoll;
}

# http 块
http {
    # http 全局块
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    
    log_format main '$remote_addr - $remote_user [$time_local]';
    access_log /var/log/nginx/access.log main;
    
    sendfile on;
    keepalive_timeout 65;
    
    # server 块
    server {
        # server 全局块
        listen 80;
        server_name example.com;
        
        # location 块
        location / {
            root /var/www/html;
            index index.html;
        }
        
        location /api {
            proxy_pass http://backend;
        }
    }
}
```

**配置层级**：
```
全局块
└── events 块
└── http 块
    └── upstream 块
    └── server 块
        └── location 块
```

---

### 3.2 常用指令

#### 全局指令

```nginx
# 运行用户
user nginx;

# Worker 进程数（auto = CPU 核心数）
worker_processes auto;

# 错误日志
error_log /var/log/nginx/error.log warn;

# PID 文件
pid /run/nginx.pid;
```

#### events 指令

```nginx
events {
    # 单个 Worker 最大连接数
    worker_connections 1024;
    
    # 事件模型（epoll/kqueue/select）
    use epoll;
    
    # 允许同时接受多个连接
    multi_accept on;
}
```

#### http 指令

```nginx
http {
    # MIME 类型
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    
    # 日志格式
    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';
    
    # 访问日志
    access_log /var/log/nginx/access.log main;
    
    # 发送文件优化
    sendfile on;
    tcp_nopush on;
    tcp_nodelay on;
    
    # 连接超时
    keepalive_timeout 65;
    
    # Gzip 压缩
    gzip on;
    gzip_types text/plain text/css application/json;
}
```

### 3.3 内置变量

```nginx
# 客户端相关
$remote_addr          # 客户端 IP
$remote_port          # 客户端端口
$remote_user          # HTTP 认证用户名

# 请求相关
$request              # 完整请求行
$request_method       # 请求方法（GET/POST）
$request_uri          # 完整请求 URI
$uri                  # 当前 URI（不含参数）
$args                 # 请求参数
$query_string         # 同 $args
$is_args              # 如果有参数，值为 "?"

# 服务器相关
$server_name          # 服务器名称
$server_port          # 服务器端口
$server_protocol      # 协议版本（HTTP/1.1）

# 响应相关
$status               # 响应状态码
$body_bytes_sent      # 发送的字节数

# 请求头
$http_host            # Host 头
$http_user_agent      # User-Agent 头
$http_referer         # Referer 头
$http_cookie          # Cookie 头

# 时间
$time_local           # 本地时间
$time_iso8601         # ISO 8601 时间

# HTTPS 相关
$scheme               # http 或 https
$https                # 如果是 HTTPS，值为 "on"
```

**使用示例**：
```nginx
location / {
    # 在响应头中返回客户端 IP
    add_header X-Real-IP $remote_addr;
    
    # 日志中记录请求时间
    access_log /var/log/nginx/access.log 
               '$remote_addr - [$time_local] "$request" $status';
    
    # 根据请求方法处理
    if ($request_method = POST) {
        return 405;
    }
}
```

## 4. 反向代理

### 4.1 什么是反向代理？

**正向代理**：客户端代理，访问外网
```
客户端 → 正向代理 → 互联网
（客户端知道代理的存在）
```

**反向代理**：服务器代理，隐藏真实服务器
```
客户端 → 反向代理（Nginx）→ 后端服务器
（客户端不知道代理的存在，以为直接访问服务器）
```

---

### 4.2 基础配置

```nginx
server {
    listen 80;
    server_name example.com;
    
    # 反向代理到后端服务器
    location /api {
        proxy_pass http://localhost:3000;
        
        # 传递客户端真实 IP
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # 超时设置
        proxy_connect_timeout 30s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
        
        # 缓冲区设置
        proxy_buffering on;
        proxy_buffer_size 4k;
        proxy_buffers 8 4k;
    }
}
```

---

### 4.3 代理多个后端服务

```nginx
server {
    listen 80;
    server_name example.com;
    
    # 前端静态资源
    location / {
        root /var/www/html;
        try_files $uri $uri/ /index.html;
    }
    
    # API 服务
    location /api {
        proxy_pass http://localhost:3000;
    }
    
    # 用户服务
    location /user-service {
        proxy_pass http://localhost:4000;
    }
    
    # 订单服务
    location /order-service {
        proxy_pass http://localhost:5000;
    }
}
```

---

### 4.4 proxy_pass 的斜杠问题

```nginx
# 情况 1：proxy_pass 不带 URI（路径会完整传递）
location /api {
    proxy_pass http://backend;
}
# 请求：/api/users
# 转发：http://backend/api/users

# 情况 2：proxy_pass 带 URI（路径会替换）
location /api {
    proxy_pass http://backend/;
}
# 请求：/api/users
# 转发：http://backend/users（/api 被替换为 /）

# 情况 3：proxy_pass 带路径
location /api {
    proxy_pass http://backend/v1;
}
# 请求：/api/users
# 转发：http://backend/v1/users（/api 被替换为 /v1）

# 情况 4：location 使用正则
location ~ ^/api/(.*) {
    proxy_pass http://backend/$1;
}
# 请求：/api/users
# 转发：http://backend/users
```

## 5. 负载均衡

### 5.1 upstream 配置

```nginx
# 定义后端服务器组
upstream backend {
    server 192.168.1.10:3000;
    server 192.168.1.11:3000;
    server 192.168.1.12:3000;
}

server {
    listen 80;
    
    location /api {
        proxy_pass http://backend;
    }
}
```

---

### 5.2 负载均衡策略

#### 1. 轮询（Round Robin，默认）

```nginx
upstream backend {
    server server1.com;
    server server2.com;
    server server3.com;
}

# 请求分配：
# 请求 1 → server1
# 请求 2 → server2
# 请求 3 → server3
# 请求 4 → server1
# ...
```

**特点**：
- 平均分配请求
- 简单高效

---

#### 2. 加权轮询（Weighted Round Robin）

```nginx
upstream backend {
    server server1.com weight=3;  # 权重 3
    server server2.com weight=2;  # 权重 2
    server server3.com weight=1;  # 权重 1
}

# 请求分配（6 个请求为一轮）：
# server1: 3 个请求（50%）
# server2: 2 个请求（33%）
# server3: 1 个请求（17%）
```

**使用场景**：
- 服务器性能不同
- 优先使用高性能服务器

---

#### 3. IP Hash

```nginx
upstream backend {
    ip_hash;  # 启用 IP Hash
    server server1.com;
    server server2.com;
    server server3.com;
}

# 相同 IP 的请求总是分配到同一台服务器
# 客户端 192.168.1.100 → 始终访问 server1
```

**优点**：
- 会话保持（Session Sticky）
- 无需共享 Session

**缺点**：
- 负载可能不均衡
- IP 变化会导致会话丢失

---

#### 4. 最少连接（Least Connections）

```nginx
upstream backend {
    least_conn;  # 启用最少连接
    server server1.com;
    server server2.com;
    server server3.com;
}

# 请求分配给当前连接数最少的服务器
```

**适用场景**：
- 请求处理时间差异大
- 后端服务器性能差异大

---

#### 5. 一致性哈希（需要第三方模块）

```nginx
upstream backend {
    hash $request_uri consistent;
    server server1.com;
    server server2.com;
    server server3.com;
}

# 根据 URI 哈希分配
# 相同 URI 总是分配到同一台服务器
```

**使用场景**：
- 缓存服务器
- 分布式存储

---

### 5.3 健康检查

```nginx
upstream backend {
    server server1.com max_fails=3 fail_timeout=30s;
    server server2.com max_fails=3 fail_timeout=30s;
    server server3.com max_fails=3 fail_timeout=30s;
    
    # max_fails：失败 3 次后标记为不可用
    # fail_timeout：30 秒后重新尝试
}
```

**高级健康检查（Nginx Plus 或第三方模块）**：
```nginx
upstream backend {
    server server1.com;
    server server2.com;
    server server3.com;
    
    # 主动健康检查
    health_check interval=5s fails=3 passes=2;
}
```

### 5.4 备份服务器

```nginx
upstream backend {
    server server1.com;
    server server2.com;
    server backup.com backup;  # 备份服务器
}

# 只有当 server1 和 server2 都不可用时，才使用 backup.com
```

### 5.5 完整示例

```nginx
upstream api_servers {
    # 加权轮询
    server 192.168.1.10:3000 weight=3 max_fails=2 fail_timeout=10s;
    server 192.168.1.11:3000 weight=2 max_fails=2 fail_timeout=10s;
    server 192.168.1.12:3000 weight=1 max_fails=2 fail_timeout=10s;
    server 192.168.1.20:3000 backup;  # 备份服务器
    
    # 长连接优化
    keepalive 32;
    keepalive_timeout 60s;
    keepalive_requests 100;
}

server {
    listen 80;
    server_name api.example.com;
    
    location /api {
        proxy_pass http://api_servers;
        
        # 代理配置
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        
        # 超时设置
        proxy_connect_timeout 5s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
        
        # 重试
        proxy_next_upstream error timeout http_500 http_502 http_503;
        proxy_next_upstream_tries 2;
    }
}
```

```nginx
    # 静态资源根目录
```

---

### 6.2 按文件类型配置

```nginx
server {
    listen 80;
    server_name example.com;
    root /var/www/html;
    
    # HTML 文件（不缓存）
    location ~ \.html$ {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }
    
    # CSS/JS 文件（长期缓存，文件名带哈希）
    location ~ \.(css|js)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        etag off;
    }
    
    # 图片文件
    location ~ \.(jpg|jpeg|png|gif|svg|ico)$ {
        expires 30d;
        add_header Cache-Control "public";
    }
    
    # 字体文件
    location ~ \.(woff|woff2|ttf|eot)$ {
        expires 1y;
        add_header Cache-Control "public";
        add_header Access-Control-Allow-Origin *;
    }
}
```

### 6.3 Gzip 压缩

```nginx
http {
    # 启用 Gzip
    gzip on;
    
    # 压缩级别（1-9，越高压缩率越高，CPU 消耗越大）
    gzip_comp_level 6;
    
    # 最小压缩文件大小
    gzip_min_length 1000;
    
    # 压缩的 MIME 类型
    gzip_types
        text/plain
        text/css
        text/xml
        text/javascript
        application/json
        application/javascript
        application/xml+rss
        application/atom+xml
        image/svg+xml;
    
    # 禁用 IE6 的 Gzip
    gzip_disable "msie6";
    
    # 代理资源也压缩
    gzip_proxied any;
    
    # 添加 Vary: Accept-Encoding 响应头
    gzip_vary on;
    
    # Gzip 缓冲区
    gzip_buffers 16 8k;
}
```

## 7. HTTPS 配置

### 7.1 基础 HTTPS 配置

```nginx
server {
    listen 443 ssl http2;
    server_name example.com;
    
    # SSL 证书
    ssl_certificate /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;
    
    # SSL 协议
    ssl_protocols TLSv1.2 TLSv1.3;
    
    # 加密套件
    ssl_ciphers 'ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384';
    ssl_prefer_server_ciphers on;
    
    # SSL Session 缓存
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;
    
    # HSTS
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    
    location / {
        root /var/www/html;
        index index.html;
    }
}

# HTTP 跳转 HTTPS
server {
    listen 80;
    server_name example.com;
    return 301 https://$server_name$request_uri;
}
```

## 8. 缓存配置

### 8.1 代理缓存

```nginx
# http 块中定义缓存路径
http {
    proxy_cache_path /var/cache/nginx/proxy
                     levels=1:2
                     keys_zone=api_cache:10m
                     max_size=1g
                     inactive=60m
                     use_temp_path=off;
}

server {
    listen 80;
    server_name example.com;
    
    location /api {
        proxy_pass http://backend;
        
        # 启用缓存
        proxy_cache api_cache;
        
        # 缓存状态码和时间
        proxy_cache_valid 200 10m;
        proxy_cache_valid 404 1m;
        
        # 缓存键
        proxy_cache_key "$scheme$proxy_host$request_uri";
        
        # 添加缓存状态头
        add_header X-Cache-Status $upstream_cache_status;
        
        # 缓存锁（防止缓存击穿）
        proxy_cache_lock on;
        proxy_cache_lock_timeout 5s;

        proxy_cache_use_stale error timeout http_500 http_502 http_503;
    }
}
```

**缓存状态**：
- `MISS`：未命中，从后端获取
- `HIT`：命中缓存
- `EXPIRED`：缓存过期
- `STALE`：使用过期缓存
- `UPDATING`：正在更新缓存
- `BYPASS`：绕过缓存

## 12. 面试高频问答

### Q1: Nginx 和 Apache 有什么区别？

**答案**：

| 特性 | Nginx | Apache |
|------|-------|--------|
| **架构** | 事件驱动（异步非阻塞）| 进程/线程驱动 |
| **并发性能** | 高（数万连接）| 中（数千连接）|
| **内存占用** | 低 | 高 |
| **静态资源** | 快 | 慢 |
| **动态内容** | 需要反向代理到 PHP-FPM 等 | 内置模块支持（mod_php）|
| **配置** | 简洁 | 复杂（.htaccess）|
| **模块** | 编译时确定 | 动态加载 |

**Nginx 优势**：
- 高并发、低内存
- 反向代理、负载均衡
- 静态资源处理快

**Apache 优势**：
- 功能丰富、模块多
- .htaccess 支持
- 动态内容处理方便

---

### Q2: Nginx 的工作原理是什么？

**答案**：

**Master-Worker 模型**：
```
Master 进程：
- 读取配置文件
- 管理 Worker 进程
- 处理信号（重启、停止）
- 监听端口（传递给 Worker）

Worker 进程：
- 处理客户端请求
- 事件驱动（epoll/kqueue）
- 异步非阻塞 I/O
```

**事件驱动架构**：
```
Worker 进程维护事件队列
├── 新连接事件
├── 读事件
├── 写事件
└── 定时器事件

单个 Worker 处理数万连接
无需为每个连接创建线程/进程
```

**优势**：
- 高并发：一个进程处理数万连接
- 低内存：无需为每个连接分配内存
- 高性能：零拷贝、异步 I/O

---

### Q3: 什么是反向代理？和正向代理有什么区别？

**答案**：

**正向代理**：代理客户端，隐藏客户端
```
客户端 → 正向代理 → 目标服务器

客户端知道代理存在
目标服务器不知道真实客户端
```

**反向代理**：代理服务器，隐藏服务器
```
客户端 → 反向代理 → 后端服务器

客户端不知道代理存在（以为直接访问服务器）
后端服务器对外隐藏
```

**反向代理的作用**：
1. **负载均衡**：分发请求到多台服务器
2. **安全保护**：隐藏真实服务器 IP
3. **缓存**：缓存静态资源
4. **SSL 终止**：统一处理 HTTPS
5. **压缩**：统一 Gzip 压缩

### Q4: Nginx 有哪些负载均衡策略？

**答案**：

**1. 轮询（Round Robin，默认）**
```nginx
upstream backend {
    server server1.com;
    server server2.com;
}
# 平均分配请求
```

**2. 加权轮询（Weighted Round Robin）**
```nginx
upstream backend {
    server server1.com weight=3;
    server server2.com weight=1;
}
# 按权重分配（3:1）
```

**3. IP Hash**
```nginx
upstream backend {
    ip_hash;
    server server1.com;
    server server2.com;
}
# 相同 IP 总是访问同一服务器（会话保持）
```

**4. 最少连接（Least Connections）**
```nginx
upstream backend {
    least_conn;
    server server1.com;
    server server2.com;
}
# 请求分配给连接数最少的服务器
```

**选择建议**：
- 轮询：默认选择
- 加权轮询：服务器性能不同时
- IP Hash：需要会话保持时
- 最少连接：请求处理时间差异大时

### Q5: proxy_pass 加不加斜杠有什么区别？

**答案**：

```nginx
# 不加斜杠：完整路径传递
location /api {
    proxy_pass http://backend;
}
# /api/users → http://backend/api/users

# 加斜杠：路径替换
location /api {
    proxy_pass http://backend/;
}
# /api/users → http://backend/users

# 带路径：路径拼接
location /api {
    proxy_pass http://backend/v1;
}
# /api/users → http://backend/v1/users
```

**记忆方法**：
- 不带 URI（斜杠）→ 完整传递
- 带 URI（斜杠或路径）→ 替换 location 匹配部分

### Q6: 如何实现灰度发布？

**答案**：

**方案 1：基于 Cookie**
```nginx
upstream stable {
    server stable1.com;
}

upstream canary {
    server canary1.com;
}

server {
    location / {
        # 检查 Cookie
        if ($http_cookie ~* "canary=true") {
            proxy_pass http://canary;
            break;
        }
        
        proxy_pass http://stable;
    }
}
```

**方案 2：基于 IP**
```nginx
geo $canary {
    default 0;
    192.168.1.0/24 1;  # 这个 IP 段使用灰度版本
}

server {
    location / {
        if ($canary) {
            proxy_pass http://canary;
            break;
        }
        
        proxy_pass http://stable;
    }
}
```

**方案 3：基于权重（split_clients）**
```nginx
split_clients "${remote_addr}" $variant {
    10%     canary;  # 10% 流量到灰度
    *       stable;
}

server {
    location / {
        proxy_pass http://$variant;
    }
}
```

  ```bash
  tail -f /var/log/nginx/error.log
  ```
- **解决**：启动后端服务，检查防火墙

**503 Service Unavailable**：
- **原因**：后端服务器全部不可用
- **排查**：检查 upstream 健康检查
- **解决**：恢复后端服务

**504 Gateway Timeout**：
- **原因**：后端响应超时
- **排查**：
  ```nginx
  # 查看超时配置
  proxy_connect_timeout 60s;
  proxy_read_timeout 60s;
  ```
- **解决**：增加超时时间，优化后端性能

### Q10: Nginx 如何配置 HTTPS？

**答案**：

**完整配置**：
```nginx
server {
    listen 443 ssl http2;
    server_name example.com;
    
    # SSL 证书
    ssl_certificate /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;
    
    # SSL 协议（只使用 TLS 1.2/1.3）
    ssl_protocols TLSv1.2 TLSv1.3;
    
    # 加密套件
    ssl_ciphers 'ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384';
    ssl_prefer_server_ciphers on;
    
    # Session 缓存
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;
    
    # OCSP Stapling
    ssl_stapling on;
    ssl_stapling_verify on;
    
    # HSTS
    add_header Strict-Transport-Security "max-age=31536000" always;
}

# HTTP 跳转 HTTPS
server {
    listen 80;
    server_name example.com;
    return 301 https://$server_name$request_uri;
}
```

```bash
# 安装 Certbot
sudo apt install certbot python3-certbot-nginx

# 申请证书
sudo certbot --nginx -d example.com

# 自动续期
sudo certbot renew
```
