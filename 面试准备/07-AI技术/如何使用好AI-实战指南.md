## 1. 为什么前端要用 AI

### 1.1 效率提升

```
传统方式 vs AI 方式：

写一个复杂组件：
❌ 传统：2小时查文档 + 写代码 + 调试
✅ AI：10分钟描述需求 + 30分钟调整 = 省 75% 时间

调试奇怪的 Bug：
❌ 传统：Google 1小时 + 试错 1小时
✅ AI：描述问题 + 5分钟得到答案 = 省 90% 时间

学习新技术：
❌ 传统：看文档 2小时 + 看视频 2小时
✅ AI：对话式学习 30分钟 = 省 80% 时间

## 4. 高级技巧

### 4.1 Chain of Thought（思维链）

**原理**：让 AI 一步步思考，而不是直接给答案

**❌ 直接问**
```
这个性能问题怎么解决？
```

**✅ 引导思考**
```
请帮我分析这个性能问题，按以下步骤：

第一步：问题定位
- 慢在哪里？（加载、渲染、交互）
- 如何测量？（工具、指标）

第二步：原因分析
- 可能是什么导致的？（列出 3-5 个）
- 哪个最有可能？

第三步：解决方案
- 针对最可能的原因，给出方案
- 预期效果
- 实施难度

第四步：验证方法
- 如何验证优化效果？

按步骤给出你的分析。
```

---

### 4.2 Few-Shot Learning（举例学习）

**原理**：给 AI 几个示例，让它模仿

**示例：代码风格统一**
```
请按我的代码风格重构以下代码。

我的风格示例：

示例 1：
\`\`\`tsx
// ❌ 不好的写法
function UserCard(props) {
  return <div>{props.name}</div>;
}

// ✅ 我的风格
interface UserCardProps {
  name: string;
  email: string;
}

export const UserCard: React.FC<UserCardProps> = ({ name, email }) => {
  return (
    <div className="user-card">
      <h3>{name}</h3>
      <p>{email}</p>
    </div>
  );
};
\`\`\`

示例 2：
\`\`\`tsx
// ❌ 不好的写法
const data = users.filter(u => u.age > 18).map(u => u.name);

// ✅ 我的风格
const adultUserNames = users
  .filter((user) => user.age > 18)
  .map((user) => user.name);
\`\`\`

现在请按我的风格重构这段代码：
\`\`\`tsx
[待重构的代码]
\`\`\`
```

### 4.3 Iterative Refinement（迭代优化）

**原理**：不要期望一次完美，多轮对话优化

```

```

**第 2 轮：补充需求**
```

- 支持虚拟滚动（10w+ 数据）
- 支持列宽拖拽调整
- 支持列冻结
请在原代码基础上增加这些功能
```

**第 3 轮：性能优化**
```
当前表格在 5w 数据时有点卡，请优化性能
重点优化渲染性能
```

**第 4 轮：细节完善**
```
请添加：
- 单元测试（Jest + RTL）
- Storybook 文档
- TypeScript 类型导出
```

## 5. 避坑指南

### 5.1 常见误区

#### ❌ 误区 1：完全依赖 AI
```
问题：
- 不思考就问 AI
- 不理解就复制代码
- 出问题就怪 AI

后果：
- 技能退化
- 无法应对面试
- 遇到复杂问题束手无策

正确做法：
- 先自己思考 5 分钟
- 理解 AI 给的代码
- 验证代码是否正确
- 学习背后的原理
```

#### ❌ 误区 2：问题描述不清
```
差的提问：
"帮我写个组件"
"为什么报错"
"怎么优化性能"

好的提问：
- 需求清晰（要做什么）
- 限制明确（技术栈、不能用什么）
- 期望输出（代码、解释、对比）
```

#### ❌ 误区 3：不验证答案
```
问题：
- AI 可能给错误答案
- 可能是过时的方案
- 可能不适合你的场景

正确做法：
✅ 阅读并理解代码
✅ 跑一遍，测试是否正常
✅ 查官方文档确认
✅ 多问一句"还有更好的方案吗？"
```

### 5.2 安全注意事项

#### ⚠️ 不要泄露敏感信息

```
❌ 不要发给 AI：
- 公司源码（完整项目）
- API 密钥
- 用户数据
- 商业机密
- 内部文档

✅ 可以发：
- 脱敏的代码片段
- 通用的问题
- 公开的技术方案
```

**脱敏方法**：
```typescript
// ❌ 直接发
const API_KEY = 'sk_live_abc123xyz';

// ✅ 脱敏后发
const API_KEY = 'YOUR_API_KEY'; // 实际使用时替换
```
