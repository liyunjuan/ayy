## 完整流程概览

```
URL输入
  ↓
DNS解析
  ↓
TCP连接（三次握手）
  ↓
发送HTTP请求
  ↓
服务器处理并返回响应
  ↓
浏览器接收响应
  ↓
解析HTML → 构建DOM树
  ↓
解析CSS → 构建CSSOM树
  ↓
执行JavaScript
  ↓
合成渲染树（Render Tree）
  ↓
布局计算（Layout/Reflow）
  ↓
绘制（Paint）
  ↓
合成显示（Composite）
  ↓
TCP连接关闭（四次挥手）
```

## 详细步骤解析

### 1️⃣ URL解析与缓存检查

**过程：**
```javascript
// URL结构示例
https://www.example.com:443/path/page?query=1#hash

// 解析内容
{
  protocol: 'https',
  host: 'www.example.com',
  port: 443,
  path: '/path/page',
  query: 'query=1',
  hash: '#hash'
}
```

**缓存检查顺序：**
1. **强缓存**：检查 `Cache-Control`、`Expires`
   - 命中直接返回，状态码 200（from disk cache / memory cache）
2. **协商缓存**：检查 `ETag`、`Last-Modified`
   - 发送请求验证，304 Not Modified 则使用缓存

---

### 2️⃣ DNS解析

**查询顺序（递归+迭代）：**

```
1. 浏览器DNS缓存
   ↓ 未命中
2. 操作系统DNS缓存（/etc/hosts）
   ↓ 未命中
3. 路由器DNS缓存
   ↓ 未命中
4. ISP（运营商）DNS服务器
   ↓ 未命中
5. 根DNS服务器（.）
   ↓
6. 顶级域名服务器（.com）
   ↓
7. 权威DNS服务器（example.com）
   ↓
返回IP地址
```

**优化手段：**
```html
<!-- DNS预解析 -->
<link rel="dns-prefetch" href="//api.example.com">

<!-- 预连接（DNS + TCP + TLS） -->
<link rel="preconnect" href="//cdn.example.com">
```

---

### 3️⃣ 建立TCP连接（三次握手）

```
客户端                        服务器
  |                              |
  |-------- SYN（seq=x）-------->|  第一次握手
  |                              |
  |<---- SYN+ACK（seq=y,ack=x+1）-| 第二次握手
  |                              |
  |-------- ACK（ack=y+1）------->| 第三次握手
  |                              |
  |       连接建立（ESTABLISHED） |
```

**为什么需要三次握手？**
- 防止旧连接请求突然到达服务器造成错误
- 确认双方收发能力正常
- 协商初始序列号（ISN）

**HTTPS额外步骤（TLS握手）：**
1. ClientHello：客户端发送支持的加密套件
2. ServerHello：服务器选择加密套件并发送证书
3. 客户端验证证书
4. 密钥交换（RSA/ECDHE）
5. 加密通信开始

---

### 4️⃣ 发送HTTP请求

**请求报文结构：**
```http
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: text/html,application/xhtml+xml
Accept-Encoding: gzip, deflate, br
Connection: keep-alive
Cookie: session=abc123

[请求体（POST时存在）]
```

**HTTP/2 改进：**
- 二进制分帧
- 多路复用（一个TCP连接处理多个请求）
- 头部压缩（HPACK）
- 服务器推送

### 5️⃣ 服务器处理请求

**典型流程：**
```
Web服务器（Nginx/Apache）
  ↓
应用服务器（Node.js/Java/PHP）
  ↓
业务逻辑处理
  ↓
数据库查询（MySQL/Redis）
  ↓
构建响应
  ↓
返回HTTP响应
```

---

### 6️⃣ 浏览器接收HTTP响应

**响应报文结构：**
```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 12345
Cache-Control: max-age=3600
ETag: "abc123"
Last-Modified: Wed, 21 Jun 2026 10:00:00 GMT

<!DOCTYPE html>
<html>...</html>
```

**常见状态码：**
- `200 OK`：成功
- `304 Not Modified`：协商缓存命中
- `301/302`：重定向
- `404 Not Found`：资源不存在
- `500 Internal Server Error`：服务器错误

### 7️⃣ 解析HTML构建DOM树

**解析过程：**
```javascript
// 1. 词法分析（Tokenization）
"<div id='app'>" → [StartTag, Attribute, ...]

// 2. 语法分析（Parsing）
Tokens → DOM节点

// 3. 构建DOM树
document
  └─ html
      ├─ head
      │   ├─ title
      │   └─ meta
      └─ body
          └─ div#app
              ├─ p
              └─ span
```

**关键点：**
- HTML解析是**渐进式**的（边下载边解析）
- 遇到 `<script>` 默认会**阻塞解析**（除非有 async/defer）
- 遇到 `<img>`、`<link>` 等资源会**异步加载**

---

### 8️⃣ 解析CSS构建CSSOM树

**CSS来源：**
1. 外部样式表 `<link>`
2. 内部样式 `<style>`
3. 内联样式 `style="..."`
4. 浏览器默认样式

**CSSOM树结构：**
```javascript
// CSS规则
body { font-size: 16px; }
div { color: red; }
.class { margin: 10px; }

// CSSOM树
document
  └─ body (font-size: 16px)
      └─ div (color: red, font-size: 16px)
          └─ .class (margin: 10px, color: red, font-size: 16px)
```

**注意：**
- CSS解析**不会阻塞DOM解析**
- CSS会**阻塞渲染**（CSSOM未构建完成前不渲染）
- CSS会**阻塞JS执行**（JS可能查询样式）

---

### 9️⃣ 执行JavaScript

**脚本加载方式：**

| 方式 | 特点 | 使用场景 |
|------|------|----------|
| `<script src="...">` | 阻塞HTML解析 | 依赖DOM的脚本 |
| `<script async>` | 异步下载，下载完立即执行 | 独立脚本（统计） |
| `<script defer>` | 异步下载，DOMContentLoaded前执行 | 需操作DOM的脚本 |
| `<script type="module">` | 自动defer，支持ES6模块 | 现代应用 |

**执行时机：**
```javascript
// 1. DOMContentLoaded 事件
document.addEventListener('DOMContentLoaded', () => {
  // DOM构建完成，资源可能未加载
});

// 2. load 事件
window.addEventListener('load', () => {
  // 所有资源（图片、CSS等）加载完成
});
```

### 🔟 构建渲染树（Render Tree）

**渲染树 = DOM树 + CSSOM树**

```
DOM树                CSSOM树              渲染树
html                body {font:16px}     html
 ├─body              div {display:none}    └─body
 │  ├─div(none)      p {color:red}            └─p
 │  └─p                                           color:red
 │     └─"text"                                   font:16px
```

**不包含的节点：**
- `display: none` 的元素
- `<head>`、`<script>`、`<meta>` 等不可见标签
- 伪元素 `::before`、`::after` **会包含**

### 1️⃣1️⃣ 布局（Layout / Reflow）

**计算内容：**
- 元素的几何位置（x, y）
- 元素的尺寸（width, height）
- 盒模型计算（margin, padding, border）

**触发重排的操作：**
```javascript
// ❌ 强制同步布局（会导致多次重排）
div.style.width = '100px';
const height = div.offsetHeight; // 触发重排
div.style.height = height + 'px'; // 再次触发重排

// ✅ 批量修改（只触发一次重排）
div.style.cssText = 'width: 100px; height: 200px;';

// ✅ 使用DocumentFragment
const fragment = document.createDocumentFragment();
// ...批量操作
document.body.appendChild(fragment); // 一次性插入
```

**常见触发重排的属性：**
- 添加/删除DOM节点
- 修改元素尺寸：`width`、`height`、`padding`、`margin`
- 读取布局信息：`offsetTop`、`scrollTop`、`clientWidth`
- 修改字体大小
- 浏览器窗口大小变化

---

### 1️⃣2️⃣ 绘制（Paint）

**绘制内容：**
- 文本
- 颜色（color、background）
- 边框（border）
- 阴影（box-shadow、text-shadow）
- 图片

**触发重绘的操作：**
```css
/* 只触发重绘（不重排） */
color: red;
background-color: blue;
visibility: hidden;
box-shadow: 0 0 10px #000;
```

---

### 1️⃣3️⃣ 合成（Composite）

**图层分层规则：**
- 根元素
- `position: fixed/absolute` + transform/opacity
- `will-change: transform/opacity`
- `<video>`、`<canvas>`、`<iframe>`
- CSS 3D变换
- CSS滤镜

**合成层优化：**
```css
/* ✅ 只触发合成（性能最好） */
.box {
  transform: translateX(100px); /* 不触发重排和重绘 */
  opacity: 0.5;
}

/* ✅ 提升为合成层 */
.box {
  will-change: transform; /* 提示浏览器优化 */
}
```

**层爆炸问题：**
```css
/* ❌ 避免创建过多图层 */
* {
  will-change: transform; /* 导致数千个图层 */
}
```

### 1️⃣4️⃣ 资源加载与事件触发

**加载顺序：**
```
解析HTML
  ↓
DOMContentLoaded（DOM构建完成）
  ↓
加载图片、字体等资源
  ↓
load事件（所有资源加载完成）
```

**关键事件：**
```javascript
// FP（First Paint）首次绘制
performance.getEntriesByType('paint')[0];

// FCP（First Contentful Paint）首次内容绘制
performance.getEntriesByType('paint')[1];

// LCP（Largest Contentful Paint）最大内容绘制
new PerformanceObserver((list) => {
  const entries = list.getEntries();
  const lastEntry = entries[entries.length - 1];
  console.log('LCP:', lastEntry.renderTime || lastEntry.loadTime);
}).observe({ entryTypes: ['largest-contentful-paint'] });
```

### 1️⃣5️⃣ 关闭TCP连接（四次挥手）

```
客户端                        服务器
  |                              |
  |-------- FIN（seq=u）-------->|  第一次挥手
  |                              |
  |<------- ACK（ack=u+1）-------|  第二次挥手
  |                              |
  |<------- FIN（seq=v）---------|  第三次挥手
  |                              |
  |-------- ACK（ack=v+1）------->| 第四次挥手
  |                              |
  |      连接关闭（CLOSED）       |
```

**为什么需要四次挥手？**
- TCP是全双工协议（双向独立关闭）
- 服务器收到FIN后可能还有数据要发送
- 客户端需等待2MSL（Maximum Segment Lifetime）确保ACK到达

**HTTP Keep-Alive：**
```http
Connection: keep-alive
Keep-Alive: timeout=5, max=100

# 复用TCP连接，减少握手开销
```

## 关键概念深入

### 🔄 重排（Reflow）vs 重绘（Repaint）

| 对比项 | 重排（Reflow） | 重绘（Repaint） |
|--------|----------------|-----------------|
| **定义** | 重新计算元素几何属性 | 重新绘制元素外观 |
| **性能** | 影响较大 | 影响较小 |
| **触发** | 尺寸、位置变化 | 颜色、阴影变化 |
| **范围** | 可能影响整个页面 | 只影响元素本身 |
| **关系** | 重排必然重绘 | 重绘不一定重排 |

**避免频繁重排：**
```javascript
// ❌ 每次都触发重排
for (let i = 0; i < 1000; i++) {
  document.body.appendChild(createDiv());
}

// ✅ 一次性插入
const fragment = document.createDocumentFragment();
for (let i = 0; i < 1000; i++) {
  fragment.appendChild(createDiv());
}
document.body.appendChild(fragment);
```

### 🚀 关键渲染路径（Critical Rendering Path）

**组成部分：**
1. **关键资源**：阻塞渲染的资源（HTML、CSS、同步JS）
2. **关键字节**：关键资源的总大小
3. **关键路径长度**：下载关键资源的往返次数（RTT）

**优化目标：**
- ✅ 减少关键资源数量
- ✅ 减小关键资源大小
- ✅ 缩短关键路径长度

**示例分析：**
```html
<!DOCTYPE html>
<html>
<head>
  <!-- 关键资源1：CSS（阻塞渲染） -->
  <link rel="stylesheet" href="style.css">
  
  <!-- 关键资源2：同步JS（阻塞解析） -->
  <script src="app.js"></script>
</head>
<body>
  <div id="app"></div>
  
  <!-- 非关键资源：异步JS -->
  <script async src="analytics.js"></script>
</body>
</html>
```

### 📊 渲染性能指标

**Core Web Vitals（核心指标）：**

| 指标 | 含义 | 优秀值 | 测量方式 |
|------|------|--------|----------|
| **LCP** | 最大内容绘制 | < 2.5s | Largest Contentful Paint |
| **FID** | 首次输入延迟 | < 100ms | First Input Delay |
| **CLS** | 累积布局偏移 | < 0.1 | Cumulative Layout Shift |

**其他重要指标：**
- **TTFB**（Time to First Byte）：首字节时间 < 600ms
- **FCP**（First Contentful Paint）：首次内容绘制 < 1.8s
- **TTI**（Time to Interactive）：可交互时间 < 3.8s

**测量工具：**
```javascript
// 使用 Performance API
const perfData = performance.timing;
const loadTime = perfData.loadEventEnd - perfData.navigationStart;
console.log('页面加载时间:', loadTime);

// 使用 PerformanceObserver
const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    console.log(entry.name, entry.startTime);
  }
});
observer.observe({ entryTypes: ['paint', 'navigation'] });
```

### 🎨 渲染层优化

**1. 减少重排重绘**
```javascript
// ❌ 强制同步布局
const h1 = element1.clientHeight;
element1.style.height = (h1 * 2) + 'px';

const h2 = element2.clientHeight; // 触发重排
element2.style.height = (h2 * 2) + 'px';

// ✅ 分离读写操作
const h1 = element1.clientHeight;
const h2 = element2.clientHeight;
element1.style.height = (h1 * 2) + 'px';
element2.style.height = (h2 * 2) + 'px';
```

**2. 使用CSS3硬件加速**
```css
/* 只触发合成，不触发重排重绘 */
.box {
  transform: translateZ(0); /* 创建合成层 */
  will-change: transform;
}

/* 动画优先使用 transform 和 opacity */
@keyframes slide {
  from { transform: translateX(0); }
  to { transform: translateX(100px); }
}
```

**3. 防抖与节流**
```javascript
// 防抖（最后一次执行）
function debounce(fn, delay) {
  let timer = null;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// 节流（固定频率执行）
function throttle(fn, delay) {
  let last = 0;
  return function(...args) {
    const now = Date.now();
    if (now - last >= delay) {
      fn.apply(this, args);
      last = now;
    }
  };
}

// 使用
window.addEventListener('scroll', throttle(() => {
  console.log('滚动事件');
}, 200));
```

## 常见面试问题

### Q1: 为什么CSS要放在头部，JS要放在底部？

**答案：**

**CSS放头部：**
- CSS会阻塞渲染（CSSOM未构建完不渲染）
- 放头部可以边解析边构建CSSOM，避免FOUC（无样式内容闪烁）
- 放底部会导致页面先显示无样式内容，再突然应用样式

**JS放底部：**
- 同步JS会阻塞HTML解析
- 放底部可以让DOM先构建完成，用户能更快看到内容
- 现代做法：使用 `async` 或 `defer` 属性

```html
<head>
  <!-- ✅ CSS放头部 -->
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <!-- 页面内容 -->
  
  <!-- ✅ JS放底部 -->
  <script src="app.js"></script>
</body>
```

### Q2: async 和 defer 的区别？

| 对比项 | 普通script | async | defer |
|--------|-----------|-------|-------|
| **下载** | 阻塞解析 | 异步下载 | 异步下载 |
| **执行** | 立即执行 | 下载完立即执行 | DOMContentLoaded前执行 |
| **顺序** | 按出现顺序 | 不保证顺序 | 保证顺序 |
| **阻塞** | 阻塞解析 | 执行时阻塞 | 不阻塞 |

**使用场景：**
```html
<!-- 独立脚本：统计、广告 -->
<script async src="analytics.js"></script>

<!-- 依赖DOM的脚本 -->
<script defer src="app.js"></script>

<!-- 依赖顺序的脚本 -->
<script defer src="jquery.js"></script>
<script defer src="app.js"></script> <!-- 确保jquery先执行 -->
```

### Q3: 如何减少页面重排？

**答案：**

**1. 批量修改DOM**
```javascript
// ❌ 多次重排
element.style.width = '100px';
element.style.height = '200px';
element.style.border = '1px solid red';

// ✅ 一次重排
element.style.cssText = 'width:100px; height:200px; border:1px solid red';

// ✅ 使用class
element.className = 'my-style';
```

**2. 使用DocumentFragment**
```javascript
const fragment = document.createDocumentFragment();
for (let i = 0; i < 100; i++) {
  const div = document.createElement('div');
  fragment.appendChild(div);
}
document.body.appendChild(fragment); // 只触发一次重排
```

**3. 读写分离**
```javascript
// ❌ 强制同步布局
div1.style.width = div2.offsetWidth + 'px'; // 读
div2.style.height = div1.offsetHeight + 'px'; // 写（触发重排）

// ✅ 先读后写
const w = div2.offsetWidth;
const h = div1.offsetHeight;
div1.style.width = w + 'px';
div2.style.height = h + 'px';
```

**4. 使用transform代替定位**
```css
/* ❌ 触发重排 */
.box { left: 100px; }

/* ✅ 只触发合成 */
.box { transform: translateX(100px); }
```

### Q4: 什么是关键渲染路径？如何优化？

**答案：**

**定义：**
浏览器从接收HTML到首次绘制的过程中，必须完成的最少步骤。

**组成：**
1. HTML → DOM树
2. CSS → CSSOM树
3. DOM + CSSOM → 渲染树
4. 布局 → 绘制

**优化策略：**

**1. 减少关键资源数量**
```html
<!-- ❌ 多个CSS文件 -->
<link rel="stylesheet" href="style1.css">
<link rel="stylesheet" href="style2.css">

<!-- ✅ 合并为一个 -->
<link rel="stylesheet" href="bundle.css">

<!-- ✅ 非关键CSS延迟加载 -->
<link rel="preload" href="print.css" as="style" onload="this.rel='stylesheet'">
```

**2. 减小关键资源大小**
```html
<!-- 压缩、minify -->
<link rel="stylesheet" href="style.min.css">

<!-- 使用CDN -->
<link rel="stylesheet" href="https://cdn.example.com/style.css">
```

**3. 缩短关键路径长度**
```html
<!-- 内联关键CSS -->
<style>
  /* 首屏关键样式 */
  .hero { background: #000; }
</style>

<!-- 异步加载非关键CSS -->
<link rel="preload" href="other.css" as="style" onload="this.rel='stylesheet'">
```

### Q6: 如何测量首屏加载时间？

**答案：**

**方法1：Performance API**
```javascript
window.addEventListener('load', () => {
  const timing = performance.timing;
  
  // DNS查询时间
  const dnsTime = timing.domainLookupEnd - timing.domainLookupStart;
  
  // TCP连接时间
  const tcpTime = timing.connectEnd - timing.connectStart;
  
  // 请求时间
  const requestTime = timing.responseEnd - timing.requestStart;
  
  // 解析DOM时间
  const domTime = timing.domComplete - timing.domLoading;
  
  // 首屏时间
  const firstScreenTime = timing.domContentLoadedEventEnd - timing.navigationStart;
  
  console.log('首屏时间:', firstScreenTime);
});
```

**方法2：PerformanceObserver**
```javascript
// 监听FCP
new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (entry.name === 'first-contentful-paint') {
      console.log('FCP:', entry.startTime);
    }
  }
}).observe({ entryTypes: ['paint'] });

// 监听LCP
new PerformanceObserver((list) => {
  const entries = list.getEntries();
  const lastEntry = entries[entries.length - 1];
  console.log('LCP:', lastEntry.renderTime || lastEntry.loadTime);
}).observe({ entryTypes: ['largest-contentful-paint'] });
```

**方法3：MutationObserver（自定义首屏）**
```javascript
const observer = new MutationObserver(() => {
  const firstScreenElements = document.querySelectorAll('.first-screen');
  if (firstScreenElements.length > 0) {
    const firstScreenTime = performance.now();
    console.log('首屏时间:', firstScreenTime);
    observer.disconnect();
  }
});

observer.observe(document.body, {
  childList: true,
  subtree: true,
});
```

## 📚 总结

### 核心流程（面试必答）

```
1. 输入URL → 解析URL
2. DNS解析 → 获取IP地址
3. TCP三次握手 → 建立连接
4. 发送HTTP请求
5. 服务器响应
6. 解析HTML → DOM树
7. 解析CSS → CSSOM树
8. 执行JS
9. 合成渲染树
10. 布局计算
11. 绘制
12. 合成显示
13. TCP四次挥手
```

### 关键优化点

✅ **网络层**：DNS预解析、HTTP/2、CDN、缓存  
✅ **渲染层**：减少重排重绘、CSS3硬件加速、防抖节流  
✅ **资源层**：代码分割、懒加载、压缩混淆  
✅ **JavaScript**：async/defer、Web Worker、长任务拆分

### 性能指标

- **LCP** < 2.5s（最大内容绘制）
- **FID** < 100ms（首次输入延迟）
- **CLS** < 0.1（累积布局偏移）
