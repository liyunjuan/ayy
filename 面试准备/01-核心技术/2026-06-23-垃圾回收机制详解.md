## 1. 垃圾回收基础

### 1.1 什么是垃圾回收？

**垃圾回收（Garbage Collection，GC）**：自动释放不再使用的内存，防止内存泄漏。

**对比手动内存管理**：
```c
// C 语言：手动管理内存
int* ptr = (int*)malloc(sizeof(int) * 100);
// 使用 ptr
free(ptr); // 必须手动释放，否则内存泄漏

// JavaScript：自动垃圾回收
let arr = new Array(100);
// 使用 arr
// 当 arr 不再被引用时，自动回收
```

---

### 1.2 为什么需要垃圾回收？

**优点**：
- ✅ 防止内存泄漏
- ✅ 简化编程
- ✅ 提高代码安全性

**缺点**：
- ❌ 性能开销（GC 暂停）
- ❌ 不可预测的停顿
- ❌ 无法完全避免内存泄漏

---

### 1.3 如何判断对象可回收？

**核心问题**：如何判断一个对象不再被使用？

**两种主要算法**：
1. **引用计数**（Reference Counting）
2. **标记清除**（Mark-and-Sweep）

---

## 2. 引用计数

### 2.1 工作原理

**核心思想**：记录每个对象被引用的次数

```javascript
// 引用计数示例（概念演示）

let obj = { name: 'Alice' }; // obj 引用计数 = 1

let ref1 = obj; // obj 引用计数 = 2
let ref2 = obj; // obj 引用计数 = 3

ref1 = null; // obj 引用计数 = 2
ref2 = null; // obj 引用计数 = 1
obj = null;  // obj 引用计数 = 0 → 回收
```

**流程**：
```
1. 对象创建：引用计数 = 1
2. 赋值给变量：引用计数 +1
3. 变量被置空：引用计数 -1
4. 引用计数 = 0：标记为可回收
```

---

### 2.2 优缺点

**优点**：
- ✅ 实时回收（引用计数为 0 立即回收）
- ✅ 实现简单
- ✅ 无需遍历所有对象

**缺点**：
- ❌ **循环引用无法回收**（致命缺陷）
- ❌ 引用计数维护开销大
- ❌ 频繁的计数更新

---

### 2.3 循环引用问题

```javascript
// 循环引用示例
function createCycle() {
  let objA = { name: 'A' };
  let objB = { name: 'B' };
  
  objA.ref = objB; // A 引用 B
  objB.ref = objA; // B 引用 A
  
  // 即使函数结束，objA 和 objB 的引用计数都不为 0
  // 导致内存泄漏
}

createCycle();
// objA 和 objB 永远无法回收
```

**引用计数的循环引用问题**：
```
objA.ref → objB
objB.ref → objA

objA 引用计数 = 1（被 objB 引用）
objB 引用计数 = 1（被 objA 引用）

引用计数永远不为 0 → 内存泄漏
```

---

### 2.4 历史遗留问题（IE6-7）

```javascript
// IE6-7 使用引用计数管理 DOM 对象

let element = document.getElementById('myDiv');
let obj = { element: element };

element.obj = obj; // 循环引用

// 解决方案：手动解除引用
element.obj = null;
obj.element = null;
```

## 3. 标记清除

### 3.1 工作原理

**核心思想**：从根对象出发，标记所有可达对象，清除不可达对象

**根对象（GC Roots）**：
- 全局对象（window/global）
- 活动函数的局部变量和参数
- 当前执行栈上的变量

---

### 3.2 标记清除流程

```
阶段 1：标记（Mark）
┌────────────────────────────────┐
│  1. 从 GC Roots 出发           │
│  2. 遍历所有可达对象           │
│  3. 标记这些对象为"活动"       │
└────────────────────────────────┘

阶段 2：清除（Sweep）
┌────────────────────────────────┐
│  1. 遍历堆中所有对象           │
│  2. 未被标记的对象 = 垃圾      │
│  3. 回收这些对象的内存         │
└────────────────────────────────┘

阶段 3：整理（Compact，可选）
┌────────────────────────────────┐
│  1. 移动存活对象               │
│  2. 消除内存碎片               │
└────────────────────────────────┘
```

---

### 3.3 可视化示例

```javascript
// 示例代码
let obj1 = { name: 'obj1' };
let obj2 = { name: 'obj2' };
let obj3 = { name: 'obj3' };

obj1.ref = obj2; // obj1 → obj2
obj2.ref = obj3; // obj2 → obj3
obj3.ref = obj1; // obj3 → obj1（循环引用）

obj1 = null; // 断开根引用
```

**标记清除流程**：
```
初始状态：
GC Roots → obj1 → obj2 → obj3
           ↑______________|

标记阶段：
GC Roots → obj1（标记）→ obj2（标记）→ obj3（标记）

obj1 = null 后：
GC Roots   obj1 → obj2 → obj3
           （未标记）（未标记）（未标记）

清除阶段：
obj1、obj2、obj3 都未被标记 → 全部回收
```

**关键**：循环引用不影响回收！

---

### 3.4 优缺点

**优点**：
- ✅ 解决循环引用问题
- ✅ 主流浏览器和 V8 使用

**缺点**：
- ❌ 需要遍历所有对象（慢）
- ❌ GC 时需要暂停程序（Stop-The-World）
- ❌ 可能产生内存碎片

## 4. V8 垃圾回收机制

### 4.1 V8 内存结构

```
V8 堆内存（Heap）
├── 新生代（New Space）
│   ├── From 空间（Survivor From）
│   └── To 空间（Survivor To）
└── 老生代（Old Space）
    ├── 指针区（Old Pointer Space）
    └── 数据区（Old Data Space）

其他内存
├── 代码区（Code Space）
├── Map 区（Map Space）
└── 大对象区（Large Object Space）
```

**内存限制**：
```javascript
// 64 位系统
新生代：32MB（16MB From + 16MB To）
老生代：1400MB
总计：约 1.4GB

// 32 位系统
新生代：16MB
老生代：700MB
总计：约 700MB
```

---

### 4.2 分代回收

**核心思想**：根据对象存活时间采用不同策略

**分代假设**：
- 大部分对象存活时间很短（新生代）
- 少部分对象存活时间很长（老生代）

```
新生代（频繁 GC，快速）
  ↓
存活时间长 → 晋升
  ↓
老生代（少量 GC，慢速）
```

---

### 4.3 新生代回收（Scavenge 算法）

**Scavenge = Cheney 算法**：复制 + 清除

**流程**：
```
初始状态：
┌─────────────┬─────────────┐
│ From 空间   │ To 空间     │
│ obj1, obj2  │   （空）    │
│ obj3（垃圾）│             │
└─────────────┴─────────────┘

GC 触发（From 空间快满）：
1. 检查 From 空间中的对象
2. 存活对象（obj1, obj2）→ 复制到 To 空间
3. 垃圾对象（obj3）→ 不复制

复制后：
┌─────────────┬─────────────┐
│ From 空间   │ To 空间     │
│  （清空）   │ obj1, obj2  │
└─────────────┴─────────────┘

翻转：
┌─────────────┬─────────────┐
│ To 空间     │ From 空间   │
│   （空）    │ obj1, obj2  │
└─────────────┴─────────────┘
（From 和 To 角色互换）
```

**特点**：
- ✅ 速度快（只需遍历存活对象）
- ✅ 自动消除碎片（复制时整理）
- ❌ 空间浪费（只能使用一半空间）

---

### 4.4 对象晋升

**晋升条件**：
1. 对象经历过一次 Scavenge
2. To 空间使用超过 25%

```javascript
// 示例：对象晋升
function createObjects() {
  let longLived = { data: new Array(1000) };
  
  // 第一次 GC：longLived 从 From → To
  // 第二次 GC：longLived 从 To → Old Space（晋升）
  
  return longLived;
}

let obj = createObjects(); // obj 最终进入老生代
```

---

### 4.5 老生代回收（Mark-Sweep + Mark-Compact）

#### Mark-Sweep（标记清除）

```
1. 标记阶段：
   - 从 GC Roots 出发
   - 标记所有可达对象

2. 清除阶段：
   - 清除未标记对象
   - 释放内存

缺点：产生内存碎片
```

#### Mark-Compact（标记整理）

```
1. 标记阶段：同 Mark-Sweep

2. 整理阶段：
   - 将存活对象移到内存一端
   - 清除边界外的内存

优点：消除碎片
缺点：移动对象较慢
```

**V8 策略**：
- 优先使用 Mark-Sweep（快）
- 碎片过多时使用 Mark-Compact（慢）

---

### 4.6 增量标记（Incremental Marking）

**问题**：标记阶段耗时长，导致长时间停顿

**解决方案**：增量标记 = 分步执行标记

```
传统标记（Stop-The-World）：
程序暂停 → 标记 100ms → 程序恢复

增量标记：
程序运行 → 标记 10ms → 程序运行 → 标记 10ms → ...
```

**实现**：
```
1. 初始标记（快速）：标记 GC Roots 直接引用的对象
2. 并发标记（缓慢）：与 JavaScript 执行交替进行
3. 最终标记（快速）：处理并发期间的变化
```

**三色标记法**：
```
白色：未访问
灰色：已访问，子对象未访问
黑色：已访问，子对象已访问

流程：
1. 初始所有对象为白色
2. GC Roots 直接引用的对象 → 灰色
3. 逐步处理灰色对象：
   - 访问子对象 → 子对象变灰色
   - 自身变黑色
4. 最终：黑色 = 存活，白色 = 垃圾
```

---

### 4.7 并发标记（Concurrent Marking）

**更进一步**：标记与 JavaScript 执行完全并行

```
主线程（JavaScript 执行）：
程序运行 ──────────────────>

GC 线程（标记）：
标记 ───────────────────────>
```

**写屏障（Write Barrier）**：
- 记录并发期间的对象引用变化
- 确保标记的正确性

---

### 4.8 惰性清除（Lazy Sweeping）

**原理**：清除操作按需进行

```
标记完成后：
不立即清除所有垃圾，而是：
1. 程序需要分配内存时
2. 才清除部分垃圾
3. 满足分配需求即停止
```

**优点**：
- 减少 GC 停顿时间
- 提高响应速度

---

### 4.9 完整 GC 流程

```
新生代 GC（Minor GC / Scavenge）：
┌────────────────────────────────────┐
│ 1. From 空间快满（触发）           │
│ 2. 标记存活对象                    │
│ 3. 复制到 To 空间                  │
│ 4. 对象晋升（如果满足条件）        │
│ 5. From 和 To 角色互换             │
│ 时间：< 10ms                       │
└────────────────────────────────────┘

老生代 GC（Major GC / Full GC）：
┌────────────────────────────────────┐
│ 1. 增量标记（与程序交替）          │
│ 2. 并发标记（后台线程）            │
│ 3. 最终标记（暂停程序）            │
│ 4. 惰性清除（按需清除）            │
│ 5. 整理（可选，碎片多时）          │
│ 时间：数十到数百 ms                │
└────────────────────────────────────┘
```

## 5. 内存泄漏

### 5.1 什么是内存泄漏？

**定义**：不再使用的内存没有被及时释放

```javascript
// 内存泄漏示例
let cache = {};

function addToCache(key, value) {
  cache[key] = value; // 数据一直累积，永不释放
}

// 持续调用
setInterval(() => {
  addToCache(Date.now(), new Array(10000));
}, 100);

// 结果：内存持续增长，最终崩溃
```

---

### 5.2 常见内存泄漏场景

#### 场景 1：意外的全局变量

```javascript
// ❌ 不良实践
function foo() {
  bar = 'global variable'; // 缺少 var/let/const
  // 等价于 window.bar = 'global variable'
}
foo();

// ✅ 正确做法
function foo() {
  let bar = 'local variable';
}
```

---

#### 场景 2：被遗忘的定时器

```javascript
// ❌ 不良实践
let element = document.getElementById('button');

setInterval(() => {
  element.innerHTML = Date.now(); // element 永远无法回收
}, 1000);

// 即使 DOM 被移除，element 仍被定时器引用

// ✅ 正确做法
let element = document.getElementById('button');
let timer = setInterval(() => {
  element.innerHTML = Date.now();
}, 1000);

// 组件销毁时清除定时器
function cleanup() {
  clearInterval(timer);
  element = null;
}
```

---

#### 场景 3：闭包引用

```javascript
// ❌ 不良实践
function createClosure() {
  let largeData = new Array(1000000).fill('data');
  
  return function() {
    console.log('Closure'); // 闭包持有 largeData
  };
}

let closure = createClosure(); // largeData 永远无法回收

// ✅ 正确做法
function createClosure() {
  let largeData = new Array(1000000).fill('data');
  let smallData = largeData[0]; // 只保留需要的数据
  
  largeData = null; // 手动释放
  
  return function() {
    console.log(smallData);
  };
}
```

---

#### 场景 4：事件监听器未移除

```javascript
// ❌ 不良实践
let element = document.getElementById('button');

element.addEventListener('click', function handler() {
  console.log('Clicked');
});

// 即使 element 被移除，handler 仍引用 element

// ✅ 正确做法
function handler() {
  console.log('Clicked');
}

element.addEventListener('click', handler);

// 移除监听器
element.removeEventListener('click', handler);
element = null;
```

---

#### 场景 5：DOM 引用

```javascript
// ❌ 不良实践
let elements = {
  button: document.getElementById('button'),
  image: document.getElementById('image')
};

// 即使 DOM 被移除，elements 仍持有引用
document.body.removeChild(elements.button);

// ✅ 正确做法
let elements = {
  button: document.getElementById('button'),
  image: document.getElementById('image')
};

// 移除 DOM 后清空引用
document.body.removeChild(elements.button);
elements.button = null;
```

---

#### 场景 6：Map/Set 未清理

```javascript
// ❌ 不良实践
let map = new Map();
let element = document.getElementById('button');

map.set(element, 'metadata');

// element 被移除，但 map 仍引用它
document.body.removeChild(element);
element = null; // map 中的引用仍在

// ✅ 使用 WeakMap（弱引用）
let weakMap = new WeakMap();
let element = document.getElementById('button');

weakMap.set(element, 'metadata');

// element 被移除后，WeakMap 自动清理
document.body.removeChild(element);
element = null; // WeakMap 中的引用也消失
```

---

#### 场景 7：控制台日志

```javascript
// ❌ 生产环境保留 console.log
function processData(largeObject) {
  console.log('Processing', largeObject); // largeObject 被保留
  // 浏览器开发工具会保留日志对象
}

// ✅ 生产环境移除日志
function processData(largeObject) {
  if (process.env.NODE_ENV === 'development') {
    console.log('Processing', largeObject);
  }
}
```

### 5.3 WeakMap 和 WeakSet

**WeakMap**：键是弱引用，不阻止垃圾回收

```javascript
// Map vs WeakMap
let map = new Map();
let weakMap = new WeakMap();

let obj = { name: 'Alice' };

map.set(obj, 'value');
weakMap.set(obj, 'value');

// 对比
console.log(map.has(obj));     // true
console.log(weakMap.has(obj)); // true

obj = null;

// 下次 GC 后
console.log(map.has(obj));     // false（obj 是 null）
// 但 map 仍保留原对象的引用

console.log(weakMap.has(obj)); // false
// WeakMap 中的原对象已被回收
```

**应用场景**：
```javascript
// 场景 1：DOM 元素元数据
const metadata = new WeakMap();

function attachMetadata(element, data) {
  metadata.set(element, data);
}

let button = document.getElementById('button');
attachMetadata(button, { clicks: 0 });

// 元素被移除后，metadata 自动清理
document.body.removeChild(button);
button = null;
```

```javascript
// 场景 2：私有属性
const privateData = new WeakMap();

class User {
  constructor(name) {
    privateData.set(this, { name });
  }
  
  getName() {
    return privateData.get(this).name;
  }
}

let user = new User('Alice');
console.log(user.getName()); // Alice

user = null; // privateData 中的数据自动清理
```

## 6. 内存优化

### 6.1 减少对象创建

```javascript
// ❌ 不良实践
function processArray(arr) {
  for (let i = 0; i < arr.length; i++) {
    let temp = { index: i, value: arr[i] }; // 每次循环创建对象
    doSomething(temp);
  }
}

// ✅ 优化
function processArray(arr) {
  let temp = { index: 0, value: 0 }; // 复用对象
  for (let i = 0; i < arr.length; i++) {
    temp.index = i;
    temp.value = arr[i];
    doSomething(temp);
  }
}
```

---

### 6.2 对象池（Object Pool）

```javascript
/**
 * 对象池：复用对象，减少 GC 压力
 */
class ObjectPool {
  constructor(factory, reset, initialSize = 10) {
    this.factory = factory; // 对象工厂函数
    this.reset = reset;     // 重置对象函数
    this.pool = [];
    
    // 预创建对象
    for (let i = 0; i < initialSize; i++) {
      this.pool.push(factory());
    }
  }
  
  acquire() {
    if (this.pool.length > 0) {
      return this.pool.pop();
    }
    return this.factory();
  }
  
  release(obj) {
    this.reset(obj);
    this.pool.push(obj);
  }
}

// 使用示例：粒子系统
class Particle {
  constructor() {
    this.x = 0;
    this.y = 0;
    this.vx = 0;
    this.vy = 0;
  }
}

const particlePool = new ObjectPool(
  () => new Particle(),
  (p) => { p.x = p.y = p.vx = p.vy = 0; },
  100
);

// 创建粒子
let particle = particlePool.acquire();
particle.x = 100;
particle.y = 200;

// 释放粒子（回收到池中）
particlePool.release(particle);
```

### 6.3 避免内存抖动

```javascript
// ❌ 不良实践：频繁创建销毁
function animate() {
  let position = { x: 0, y: 0 }; // 每帧创建
  // 更新 position
  requestAnimationFrame(animate);
}

// ✅ 优化：复用对象
let position = { x: 0, y: 0 }; // 只创建一次
function animate() {
  // 更新 position
  requestAnimationFrame(animate);
}
```

### 6.4 及时解除引用

```javascript
// 场景：React 组件
class MyComponent extends React.Component {
  componentDidMount() {
    this.timer = setInterval(() => {
      this.setState({ time: Date.now() });
    }, 1000);

}
```

### 7.3 自动化内存泄漏检测

```javascript
/**
 * 简单的内存泄漏检测
 */
class MemoryLeakDetector {
  constructor() {
    this.baseline = 0;
    this.measurements = [];
  }
  
  measure() {
    const used = process.memoryUsage().heapUsed;
    this.measurements.push(used);
    
    // 保留最近 10 次测量
    if (this.measurements.length > 10) {
      this.measurements.shift();
    }
  }
  
  check() {
    if (this.measurements.length < 10) return false;
    
    // 如果内存持续增长，可能泄漏
    let increasing = 0;
    for (let i = 1; i < this.measurements.length; i++) {
      if (this.measurements[i] > this.measurements[i - 1]) {
        increasing++;
      }
    }
    
    // 80% 的测量都在增长 = 可能泄漏
    return increasing / this.measurements.length > 0.8;
  }
}

// 使用
const detector = new MemoryLeakDetector();

setInterval(() => {
  detector.measure();
  
  if (detector.check()) {
    console.warn('⚠️ 可能存在内存泄漏');
  }
}, 5000);
```

### 8.2 案例 2：事件监听器泄漏

**问题代码**：
```javascript
class ImageViewer {
  constructor() {
    this.images = [];
  }
  
  addImage(url) {
    const img = new Image();
    img.src = url;
    
    img.addEventListener('load', () => {
      this.images.push(img); // ⚠️ 事件监听器持有 img
    });
    
    img.addEventListener('error', () => {
      console.error('Failed to load', url);
    });
  }
  
  clear() {
    this.images = []; // ⚠️ 事件监听器未移除
  }
}
```

**修复**：
```javascript
class ImageViewer {
  constructor() {
    this.images = [];
    this.handlers = new WeakMap();
  }
  
  addImage(url) {
    const img = new Image();
    img.src = url;
    
    const loadHandler = () => {
      this.images.push(img);
    };
    
    const errorHandler = () => {
      console.error('Failed to load', url);
    };
    
    // 保存 handler 引用
    this.handlers.set(img, { loadHandler, errorHandler });
    
    img.addEventListener('load', loadHandler);
    img.addEventListener('error', errorHandler);
  }
  
  clear() {
    // 移除所有事件监听器
    this.images.forEach(img => {
      const handlers = this.handlers.get(img);
      if (handlers) {
        img.removeEventListener('load', handlers.loadHandler);
        img.removeEventListener('error', handlers.errorHandler);
      }
    });
    
    this.images = [];
    this.handlers = new WeakMap();
  }
}
```

### 8.4 案例 4：缓存无限增长

**问题代码**：
```javascript
class DataCache {
  constructor() {
    this.cache = {};
  }
  
  set(key, value) {
    this.cache[key] = value; // ⚠️ 无限增长
  }
  
  get(key) {

  }
```

**修复 1：LRU 缓存**
```javascript
class LRUCache {
  constructor(maxSize = 100) {
    this.maxSize = maxSize;
    this.cache = new Map();
  }
  
  set(key, value) {
    // 如果已存在，先删除（更新访问顺序）
    if (this.cache.has(key)) {
      this.cache.delete(key);
    }
    
    // 添加到末尾
    this.cache.set(key, value);
    
    // 超过容量，删除最旧的
    if (this.cache.size > this.maxSize) {
      const firstKey = this.cache.keys().next().value;
      this.cache.delete(firstKey);
    }
  }
  
  get(key) {
    if (!this.cache.has(key)) return undefined;
    
    // 更新访问顺序
    const value = this.cache.get(key);
    this.cache.delete(key);
    this.cache.set(key, value);
    
    return value;
  }
}
```

**修复 2：带过期时间的缓存**
```javascript
class TTLCache {
  constructor(ttl = 60000) {
    this.ttl = ttl;
    this.cache = new Map();
  }
  
  set(key, value) {
    this.cache.set(key, {
      value,
      expireAt: Date.now() + this.ttl
    });
  }
  
  get(key) {
    const item = this.cache.get(key);
    
    if (!item) return undefined;
    
    // 检查是否过期
    if (Date.now() > item.expireAt) {
      this.cache.delete(key);
      return undefined;
    }
    
    return item.value;
  }
  
  // 定期清理过期项
  cleanup() {
    const now = Date.now();
    for (const [key, item] of this.cache) {
      if (now > item.expireAt) {
        this.cache.delete(key);
      }
    }
  }
}
```

## 9. 面试高频问答

### Q1: JavaScript 的垃圾回收机制是什么？

**答案**：

JavaScript 使用**自动垃圾回收**，主要采用**标记清除算法**。

**工作原理**：
1. **标记阶段**：从 GC Roots（全局对象、活动函数等）出发，标记所有可达对象
2. **清除阶段**：清除未被标记的对象，释放内存

**GC Roots 包括**：
- 全局对象（window/global）
- 活动函数的局部变量
- 当前执行栈上的变量

**优点**：
- 解决循环引用问题
- 自动管理内存

**缺点**：
- GC 时需要暂停程序（Stop-The-World）
- 性能开销

---

### Q2: 引用计数和标记清除有什么区别？

**答案**：

| 特性 | 引用计数 | 标记清除 |
|------|---------|---------|
| **原理** | 记录对象被引用次数 | 从根对象标记可达对象 |
| **回收时机** | 引用计数为 0 立即回收 | GC 触发时回收 |
| **循环引用** | ❌ 无法回收 | ✅ 可以回收 |
| **性能** | 维护计数开销大 | 需要遍历对象 |
| **使用** | Python、PHP（部分）| JavaScript、Java |

**循环引用示例**：
```javascript
let objA = { ref: null };
let objB = { ref: null };

objA.ref = objB; // A → B
objB.ref = objA; // B → A

objA = null;
objB = null;

// 引用计数：objA 和 objB 的引用计数都不为 0，无法回收
// 标记清除：从 GC Roots 无法到达，可以回收
```

---

### Q3: V8 的分代回收是什么？

**答案**：

V8 将堆内存分为**新生代**和**老生代**，采用不同的回收策略。

**新生代（New Space）**：
- **大小**：32MB（64 位系统）
- **算法**：Scavenge（复制算法）
- **特点**：频繁 GC，速度快
- **对象**：存活时间短的对象

**老生代（Old Space）**：
- **大小**：1400MB（64 位系统）
- **算法**：Mark-Sweep + Mark-Compact
- **特点**：少量 GC，速度慢
- **对象**：存活时间长的对象

**对象晋升**：
- 新生代对象经历一次 Scavenge 后晋升到老生代
- 或 To 空间使用超过 25% 时提前晋升

**优势**：
- 针对不同生命周期对象优化
- 提高整体 GC 效率

---

### Q4: 什么是 Stop-The-World？如何优化？

**答案**：

**Stop-The-World（STW）**：GC 执行时暂停所有 JavaScript 代码执行。

**影响**：
- 页面卡顿
- 用户交互延迟
- 动画不流畅

**V8 优化方案**：

**1. 增量标记（Incremental Marking）**
```
传统：程序暂停 → 标记 100ms → 程序恢复

增量：程序运行 → 标记 10ms → 程序运行 → 标记 10ms → ...
```

**2. 并发标记（Concurrent Marking）**
```
主线程（JavaScript）：程序运行 ──────────>
GC 线程（标记）：     标记 ──────────────>
（完全并行）
```

**3. 惰性清除（Lazy Sweeping）**
```
标记完成后不立即清除所有垃圾
程序需要分配内存时才清除部分垃圾
```

**结果**：
- 单次 GC 停顿时间从 100ms 降低到 < 10ms

### Q6: WeakMap 和 Map 有什么区别？

**答案**：

| 特性 | Map | WeakMap |
|------|-----|---------|
| **键类型** | 任意值 | 只能是对象 |
| **引用类型** | 强引用 | 弱引用 |
| **GC** | 阻止键被回收 | 不阻止键被回收 |
| **可遍历** | ✓ | ✗ |
| **size 属性** | ✓ | ✗ |

**示例**：
```javascript
let map = new Map();
let weakMap = new WeakMap();

let obj = { name: 'Alice' };

map.set(obj, 'value');
weakMap.set(obj, 'value');

obj = null;

// Map：原对象仍被 map 引用，无法回收
// WeakMap：原对象可以被回收
```

**应用场景**：
- DOM 元素元数据
- 对象私有属性
- 缓存（不阻止对象回收）

### Q9: 什么时候会触发 GC？

**答案**：

- From 空间快满时
- 频率：数秒到数十秒

**老生代 GC（Major GC）触发条件**：
- 老生代内存不足时
- 增量标记完成后
- 频率：数分钟

**手动触发 GC**：

```javascript
// Node.js（需要 --expose-gc）
global.gc();

// 浏览器
// 无法手动触发，由引擎决定
```

**影响 GC 频率的因素**：
- 对象创建速度
- 内存分配速度
- 堆内存大小
- 程序执行状态
