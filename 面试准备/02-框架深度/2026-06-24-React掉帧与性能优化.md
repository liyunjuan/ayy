# React 掉帧现象与性能优化

> 深入理解：什么是掉帧、为什么会掉帧、Fiber 如何解决掉帧

## 一、什么是掉帧

### 1.1 帧的概念

**帧（Frame）**：屏幕刷新的最小单位，一帧就是屏幕上显示的一幅静态画面。

```
电影：24 帧/秒（24 FPS）
人眼：能感知 60 帧/秒（60 FPS）的流畅度
浏览器：通常 60 帧/秒（60 FPS）

1 帧 = 1000ms / 60 ≈ 16.67ms
```

**流畅的动画**：浏览器需要在每 16.67ms 内完成一帧的渲染工作。

### 1.2 一帧内浏览器要做什么

```
┌─────────────────── 一帧（16.67ms）────────────────────┐
│                                                        │
│  1. 输入事件处理（Input Events）           ~1ms       │
│     - click、scroll、touch 等                         │
│                                                        │
│  2. 定时器回调（Timers）                   ~1ms       │
│     - setTimeout、setInterval                         │
│                                                        │
│  3. requestAnimationFrame 回调            ~1ms       │
│                                                        │
│  4. 布局计算（Layout/Reflow）              ~3ms       │
│     - 计算元素位置和大小                               │
│                                                        │
│  5. 绘制（Paint）                          ~3ms       │
│     - 绘制像素到图层                                   │
│                                                        │
│  6. 合成（Composite）                      ~1ms       │
│     - 合成各个图层                                     │
│                                                        │
│  7. 空闲时间（Idle）                      ~6.67ms     │
│     - requestIdleCallback 可用时间                    │
│                                                        │
└────────────────────────────────────────────────────────┘
```

### 1.3 掉帧的表现

**掉帧（Frame Drop / Janky）**：浏览器无法在 16.67ms 内完成一帧的渲染，导致跳过某些帧。

**用户感知到的现象**：

```javascript
// 正常 60FPS（流畅）
Frame 1: 0ms    ✓ 渲染
Frame 2: 16ms   ✓ 渲染
Frame 3: 32ms   ✓ 渲染
Frame 4: 48ms   ✓ 渲染
Frame 5: 64ms   ✓ 渲染

// 掉帧 30FPS（卡顿）
Frame 1: 0ms    ✓ 渲染
Frame 2: 16ms   ✗ 跳过（JS 任务占用主线程）
Frame 3: 32ms   ✓ 渲染
Frame 4: 48ms   ✗ 跳过
Frame 5: 64ms   ✓ 渲染

// 严重掉帧 15FPS（明显卡顿）
Frame 1: 0ms    ✓ 渲染
Frame 2: 16ms   ✗ 跳过
Frame 3: 32ms   ✗ 跳过
Frame 4: 48ms   ✗ 跳过
Frame 5: 64ms   ✓ 渲染
```

**具体表现**：
- 🖱️ **滚动卡顿**：页面滚动不流畅，有顿挫感
- 🎨 **动画不连贯**：CSS 动画或过渡出现跳跃
- ⌨️ **输入延迟**：输入框打字有明显延迟
- 👆 **点击无响应**：按钮点击后需等待才有反应
- 📱 **列表渲染慢**：大列表滚动时白屏或闪烁

## 二、为什么会掉帧

### 2.1 浏览器渲染原理

**浏览器是单线程模型**（对于 JS 执行和页面渲染）：

```
主线程（Main Thread）
├── JavaScript 执行
├── 样式计算（Style）
├── 布局计算（Layout）
└── 绘制（Paint）

这些任务是互斥的，同一时间只能做一件事！
```

### 2.2 JS 长任务导致掉帧

```javascript
// ❌ 长任务示例：渲染大列表
function renderBigList(items) {
  const start = performance.now()
  
  items.forEach((item, index) => {
    const div = document.createElement('div')
    div.textContent = `Item ${index}: ${item}`
    div.style.height = '50px'
    div.style.border = '1px solid #ccc'

  const end = performance.now()

  // 如果 items 有 10000 条
  // 耗时可能超过 500ms
  // 在这 500ms 内：
  // - 丢失约 30 帧（500ms / 16.67ms ≈ 30）
  // - 用户看到的是页面冻结
}

const items = new Array(10000).fill('data')
renderBigList(items)
```

### 2.3 React 15 的掉帧问题

```javascript
  // 递归处理子节点

    reconcile(child)  // 不可中断的递归

// 问题场景：
function App() {
  return (
    <div>
      {/* 渲染 10000 个组件 */}
      {list.map(item => <Item key={item.id} data={item} />)}

// 执行流程：
// 1. 开始递归遍历 10000 个组件
// 2. 每个组件调用 render、创建 VNode、对比 Diff
// 3. 假设每个组件耗时 0.1ms
// 4. 总耗时：10000 * 0.1ms = 1000ms
// 5. 丢失帧数：1000ms / 16.67ms ≈ 60 帧

```

```javascript
// 4. React 渲染耗时：~500ms

```

## 三、Fiber 如何解决掉帧

### 3.1 时间切片（Time Slicing）

**核心思想**：将长任务拆分成多个小任务，每个小任务执行 5ms 后让出主线程。

```javascript
// React 15: 一次性完成（阻塞）
function render() {
  // 耗时 100ms
  processComponent1()  // 10ms
  processComponent2()  // 10ms
  processComponent3()  // 10ms
  // ... 10 个组件
  processComponent10() // 10ms
  
  // 100ms 内主线程被完全占用
  // 丢失 6 帧（100ms / 16.67ms ≈ 6）
}

// Fiber: 时间切片（可中断）
function render() {
  let startTime = performance.now()
  
  processComponent1()  // 5ms
  if (performance.now() - startTime > 5) {
    // 时间片用完，让出主线程
    requestIdleCallback(continueRender)
    return
  }
  
  processComponent2()  // 5ms
  if (performance.now() - startTime > 5) {
    requestIdleCallback(continueRender)
    return
  }
  
  // ...
  
  // 100ms 的任务被拆分成 20 个 5ms 的小任务
  // 每 5ms 让出一次主线程
  // 浏览器有机会渲染帧，不会掉帧
}
```

**时间轴对比**：

```
React 15（阻塞渲染）：
0ms    16ms   32ms   48ms   64ms   80ms   96ms   112ms
├──────┴──────┴──────┴──────┴──────┴──────┴──────┤
│              React Render (100ms)               │
│  用户感受：页面冻结，无法交互                      │
└─────────────────────────────────────────────────┘

Fiber（时间切片）：
0ms    16ms   32ms   48ms   64ms   80ms   96ms   112ms
├──────┼──────┼──────┼──────┼──────┼──────┼──────┤
│ 5ms  │ 5ms  │ 5ms  │ 5ms  │ 5ms  │ 5ms  │ 5ms  │
│Render│Paint │Render│Paint │Render│Paint │Render│
│  用户感受：页面流畅，可以交互                      │
└──────┴──────┴──────┴──────┴──────┴──────┴──────┘
```

### 3.2 可中断渲染

```javascript
// packages/scheduler/src/forks/Scheduler.js

// 时间片大小
let frameInterval = 5  // 5ms

// 判断是否需要让出主线程
function shouldYieldToHost() {
  const timeElapsed = getCurrentTime() - startTime
  
  if (timeElapsed < frameInterval) {
    // 还有时间，继续执行
    return false
  }
  
  // 时间片用完，让出主线程
  return true
}

// 工作循环
function workLoopConcurrent() {
  // 可中断的循环
  while (workInProgress !== null && !shouldYield()) {
    performUnitOfWork(workInProgress)
  }
  
  // 如果还有工作没完成，调度下一个时间片
  if (workInProgress !== null) {
    return RootInProgress  // 继续
  }
  
  return RootCompleted  // 完成
}
```

**具体流程**：

```javascript
// 示例：渲染 10 个组件，每个 10ms

// 第一个时间片（5ms）
workLoopConcurrent()
  processComponent1()  // 完成
  shouldYield() ? → 还没到 5ms，继续
  processComponent2()  // 进行到一半（5ms 用完）
  shouldYield() ? → 时间片用完，暂停
  // 返回，让出主线程

// 浏览器：渲染一帧（16ms）
// - 处理用户输入
// - 执行动画
// - 绘制页面

// 第二个时间片（5ms）
workLoopConcurrent()
  processComponent2()  // 继续完成
  processComponent3()  // 进行到一半
  shouldYield() ? → 时间片用完，暂停

// 如此反复，直到所有组件处理完成
```

### 3.3 优先级调度

```javascript
// 不同优先级的更新

// 场景：用户正在输入，同时有动画在运行
function App() {
  const [inputValue, setInputValue] = useState('')
  const [animationData, setAnimationData] = useState([])
  
  const handleInput = (e) => {
    // 高优先级：用户输入必须立即响应
    setInputValue(e.target.value)  // InputContinuousLane
  }
  
  useEffect(() => {
    // 低优先级：动画更新可以延后
    setInterval(() => {
      setAnimationData(generateData())  // DefaultLane
    }, 100)
  }, [])
  
  return (
    <>
      <input value={inputValue} onChange={handleInput} />
      <AnimationChart data={animationData} />
    </>
  )
}

// Fiber 的调度策略：
// 1. 用户输入时，中断动画更新
// 2. 优先处理 inputValue 的更新
// 3. 输入更新完成后，再继续动画更新
// 4. 保证用户交互的流畅性
```

**优先级调度流程**：

```
时间轴：
0ms        20ms       40ms       60ms       80ms
├──────────┼──────────┼──────────┼──────────┤

正在执行低优先级任务（动画更新）：
0ms: 开始处理动画组件 1
5ms: 处理动画组件 2
10ms: 🚨 用户输入！（高优先级）
     ↓
     中断当前任务
     保存当前状态
     ↓
15ms: 立即处理输入更新（高优先级）
20ms: 输入更新完成，提交渲染
     ↓
25ms: 恢复之前的动画更新（低优先级）
30ms: 继续处理动画组件 3
...

结果：
✅ 用户输入立即响应（20ms 内完成）
✅ 动画更新被延后，但不影响体验
```

### 3.4 Fiber 架构对比

```javascript
// React 15: Stack Reconciler（递归）
function reconcileChildren(element) {
  // 🔴 问题：递归调用，无法中断
  element.children.forEach(child => {
    reconcileChildren(child)
  })
}

// Fiber: 链表 + 循环（可中断）
function workLoopConcurrent() {
  // ✅ 优点：循环可以随时中断
  while (workInProgress !== null) {
    if (shouldYield()) {
      // 时间片用完，暂停
      return RootInProgress
    }
    
    // 处理当前 Fiber 节点
    workInProgress = performUnitOfWork(workInProgress)
  }
  
  return RootCompleted
}

// Fiber 节点链表结构
function performUnitOfWork(fiber) {
  // 1. 处理当前节点
  beginWork(fiber)
  
  // 2. 有子节点，返回子节点
  if (fiber.child) {
    return fiber.child
  }
  
  // 3. 没有子节点，找兄弟节点
  let nextFiber = fiber
  while (nextFiber) {
    completeWork(nextFiber)
    
    if (nextFiber.sibling) {
      return nextFiber.sibling
    }
    
    // 4. 没有兄弟节点，返回父节点
    nextFiber = nextFiber.return
  }
  
  return null
}

// 关键区别：
// - 递归：使用调用栈，无法暂停
// - 链表 + 循环：使用数据结构存储状态，可以随时暂停和恢复
```

### 4.4 使用 React 18 的并发特性

## 五、面试高频问题

### Q1: 什么是掉帧？如何检测？

**回答要点**：

1. **定义**：浏览器无法在 16.67ms 内完成一帧的渲染，导致跳过某些帧
2. **表现**：页面卡顿、动画不流畅、输入延迟
3. **原因**：JS 长任务占用主线程，阻塞渲染
4. **检测**：Chrome DevTools Performance 面板、PerformanceObserver API

### Q2: React 15 为什么会掉帧？

**回答要点**：

1. **递归更新**：Stack Reconciler 使用递归，一旦开始无法中断
2. **同步渲染**：必须一次性完成所有组件的 diff 和渲染
3. **长任务阻塞**：大组件树渲染可能耗时数百毫秒，阻塞主线程
4. **用户体验差**：无法响应用户输入，页面冻结

### Q3: Fiber 如何解决掉帧？

**回答要点**：

1. **时间切片**：将长任务拆分成 5ms 的小任务，执行后让出主线程
2. **可中断渲染**：链表 + 循环代替递归，可随时暂停和恢复
3. **优先级调度**：高优先级任务可以中断低优先级任务
4. **增量渲染**：Render 阶段可中断，Commit 阶段不可中断

### Q4: 为什么时间切片是 5ms？

**回答要点**：

1. **一帧 16.67ms**：除去浏览器渲染工作（~10ms），剩余 ~6ms
2. **5ms 经验值**：留有余量，保证浏览器有时间处理其他工作
3. **灵活调整**：React 内部可根据设备性能动态调整
4. **权衡**：太短频繁切换开销大，太长影响流畅性

### Q5: 如何避免掉帧？

**回答要点**：

1. **避免长任务**：使用 useMemo、useCallback 缓存计算
2. **虚拟滚动**：大列表使用 react-window、react-virtualized
3. **懒加载**：React.lazy、Suspense 按需加载组件
4. **并发特性**：startTransition、useDeferredValue 标记低优先级更新
5. **Web Worker**：将密集计算移到 Worker 线程

## 六、总结

### 核心要点

1. **掉帧**：浏览器无法在 16.67ms 内完成一帧的渲染
2. **原因**：JS 长任务占用主线程，阻塞渲染
3. **Fiber 解决方案**：时间切片 + 可中断 + 优先级调度
4. **最佳实践**：缓存计算、虚拟滚动、并发特性

### 学习建议

1. **动手实践**：在 Chrome DevTools 中观察掉帧现象
2. **性能监控**：在实际项目中添加 FPS 监控
3. **压力测试**：渲染大列表、复杂计算，观察性能表现
4. **对比优化**：优化前后对比 FPS 和主线程占用
