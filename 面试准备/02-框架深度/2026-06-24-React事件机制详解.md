# React 事件机制详解

> 面试重点：合成事件原理、事件委托、事件池优化、React 17+ 的变化

## 一、核心概念

### 1.1 什么是合成事件（SyntheticEvent）

React 基于浏览器的事件机制实现了一套自己的事件系统，称为**合成事件**：

```jsx
// React 事件
<button onClick={handleClick}>点击</button>

// 原生 DOM 事件
document.getElementById('btn').addEventListener('click', handleClick)
```

**合成事件的特点**：
- 跨浏览器兼容性（抹平不同浏览器差异）
- 统一的事件对象接口（符合 W3C 标准）
- 事件委托机制（性能优化）
- 事件池管理（React 16 及以前，React 17 已移除）

### 1.2 为什么需要合成事件

```javascript
// 问题1：浏览器兼容性
// IE8: event.srcElement
// 标准浏览器: event.target

// 问题2：事件对象差异
// IE: window.event
// 标准: 参数传递

// React 解决方案：统一的 SyntheticEvent
function handleClick(e) {
  e.preventDefault()      // 统一的方法
  console.log(e.target)   // 统一的属性
  console.log(e.nativeEvent) // 可访问原生事件
}
```

## 二、事件注册与委托

### 2.1 React 16 的事件委托（document）

**React 16 及以前**：所有事件委托到 `document` 上

```jsx
function App() {
  return (
    <div onClick={() => console.log('div click')}>
      <button onClick={() => console.log('button click')}>
        点击
      </button>
    </div>
  )
}

// 实际执行流程：
// 1. 用户点击 button
// 2. 原生事件冒泡到 document
// 3. React 在 document 上捕获事件
// 4. React 模拟捕获/冒泡阶段，依次触发：
//    - button 的 onClick
//    - div 的 onClick
```

**注册过程**：

```javascript
// 简化版原理
class EventRegistry {
  constructor() {
    this.listenerBank = {} // 存储组件的事件监听
  }

  // 注册阶段：组件挂载时
  registerEvent(fiber, eventType, handler) {
    // 1. 保存事件处理函数到 fiber
    fiber.stateNode[`__${eventType}`] = handler
    
    // 2. 在 document 上只注册一次该类型事件
    if (!this.listenerBank[eventType]) {
      document.addEventListener(
        eventType,
        this.dispatchEvent.bind(this, eventType),
        false // 冒泡阶段
      )
      this.listenerBank[eventType] = true
    }
  }

  // 触发阶段：用户操作时
  dispatchEvent(eventType, nativeEvent) {
    const target = nativeEvent.target
    
    // 1. 从触发节点向上收集所有 React 事件处理函数
    const listeners = []
    let fiber = target._reactFiber // 从 DOM 获取对应的 fiber
    
    while (fiber) {
      const handler = fiber.stateNode[`__${eventType}`]
      if (handler) {
        listeners.push({ fiber, handler })
      }
      fiber = fiber.return // 向上遍历 fiber 树
    }
    
    // 2. 创建合成事件对象
    const syntheticEvent = createSyntheticEvent(nativeEvent)
    
    // 3. 按冒泡顺序执行（从子到父）
    listeners.reverse().forEach(({ handler }) => {
      if (!syntheticEvent.isPropagationStopped()) {
        handler(syntheticEvent)
      }
    })
  }
}
```

### 2.2 React 17+ 的事件委托（root）

**React 17 改进**：事件委托到 `root` 容器节点

```jsx
// React 17+
const root = document.getElementById('root')
ReactDOM.render(<App />, root)

// 事件注册在 root 上，而不是 document
// 好处：
// 1. 支持多个 React 应用共存
// 2. 与原生事件混用更安全
// 3. 逐步迁移到新版本更容易
```

**对比示例**：

```html
<!DOCTYPE html>
<html>
<body>
  <div id="root">
    <button id="react-btn">React Button</button>
  </div>
  
  <script>
    // 原生事件监听
    document.addEventListener('click', () => {
      console.log('document click')
    })
    
    // React 16: React 事件在 document 上注册
    //   可能导致 stopPropagation 失效
    
    // React 17: React 事件在 root 上注册
    //   原生事件和 React 事件更好地隔离
  </script>
</body>
</html>
```

## 三、事件执行流程

### 3.1 完整的事件流

```jsx
function Parent() {
  const handleParentClick = (e) => {
    console.log('Parent onClick')
  }

  const handleParentCapture = (e) => {
    console.log('Parent onClickCapture')
  }

  return (
    <div 
      onClick={handleParentClick}
      onClickCapture={handleParentCapture}
    >
      <Child />
    </div>
  )
}

function Child() {
  const handleChildClick = (e) => {
    console.log('Child onClick')
  }

  return <button onClick={handleChildClick}>点击</button>
}

// 点击 button 输出顺序：
// 1. Parent onClickCapture  （捕获阶段：从父到子）
// 2. Child onClick           （目标阶段）
// 3. Parent onClick          （冒泡阶段：从子到父）
```

**事件流模拟实现**：

```javascript
function dispatchEventForPluginEventSystem(
  nativeEvent,
  targetContainer
) {
  // 1. 收集事件路径（从 target 到 root）
  const targetInst = getClosestInstanceFromNode(nativeEvent.target)
  const eventPath = []
  
  let instance = targetInst
  while (instance) {
    eventPath.push(instance)
    instance = instance.return
  }
  
  // 2. 捕获阶段（从父到子）
  for (let i = eventPath.length - 1; i >= 0; i--) {
    const handler = eventPath[i].onClickCapture
    if (handler) {
      handler(syntheticEvent)
      if (syntheticEvent.isPropagationStopped()) return
    }
  }
  
  // 3. 冒泡阶段（从子到父）
  for (let i = 0; i < eventPath.length; i++) {
    const handler = eventPath[i].onClick
    if (handler) {
      handler(syntheticEvent)
      if (syntheticEvent.isPropagationStopped()) return
    }
  }
}
```

### 3.2 阻止事件传播

```jsx
function Child() {
  const handleClick = (e) => {
    e.stopPropagation() // 阻止 React 事件冒泡
    console.log('Child clicked')
  }

  return <button onClick={handleClick}>点击</button>
}

function Parent() {
  const handleClick = () => {
    console.log('Parent clicked') // 不会执行
  }

  return (
    <div onClick={handleClick}>
      <Child />
    </div>
  )
}
```

**React 事件与原生事件的区别**：

```jsx
function Demo() {
  useEffect(() => {
    // 原生事件
    document.addEventListener('click', () => {
      console.log('document click')
    })
  }, [])

  const handleReactClick = (e) => {
    e.stopPropagation() // 只阻止 React 事件冒泡
    console.log('React click')
  }

  return <button onClick={handleReactClick}>点击</button>
}

// 点击按钮输出：
// React click
// document click  （原生事件仍会触发！）

// 原因：
// 1. React 事件委托在 root 上
// 2. e.stopPropagation() 只阻止 React 事件冒泡
// 3. 原生事件已经冒泡到 document 了
```

**如何同时阻止原生事件**：

```jsx
const handleClick = (e) => {
  e.stopPropagation()           // 阻止 React 事件冒泡
  e.nativeEvent.stopImmediatePropagation() // 阻止原生事件
}
```

## 四、事件池（React 16）

### 4.1 事件池优化

**React 16 及以前**：使用事件池复用合成事件对象

```jsx
function handleClick(e) {
  console.log(e.type) // 'click'
  
  setTimeout(() => {
    console.log(e.type) // null （事件对象已被重置！）
  }, 0)
}

// 原因：
// 1. React 维护一个事件对象池
// 2. 事件处理完后，对象被清空并放回池中
// 3. 下次事件触发时复用这个对象
// 4. 减少 GC 压力，提升性能
```

**解决方案**：

```jsx
// 方案1：持久化事件对象
function handleClick(e) {
  e.persist() // 告诉 React 不要回收这个事件对象
  
  setTimeout(() => {
    console.log(e.type) // 'click'
  }, 0)
}

// 方案2：提前保存需要的属性
function handleClick(e) {
  const type = e.type
  
  setTimeout(() => {
    console.log(type) // 'click'
  }, 0)
}
```

### 4.2 React 17 移除事件池

**React 17+**：不再使用事件池

```jsx
// React 17+ 可以安全使用
function handleClick(e) {
  setTimeout(() => {
    console.log(e.type) // 'click' ✅ 正常工作
  }, 0)
}

// 原因：
// 1. 现代浏览器性能提升，GC 压力不再明显
// 2. 事件池带来的困惑 > 性能收益
// 3. 简化开发者心智负担
```

## 五、常见事件处理

### 5.1 表单事件

```jsx
function Form() {
  const [value, setValue] = useState('')

  // onChange 在 React 中是实时触发的
  // 原生的 onchange 只在失去焦点时触发
  const handleChange = (e) => {
    setValue(e.target.value) // 实时更新
  }

  const handleSubmit = (e) => {
    e.preventDefault() // 阻止表单提交
    console.log('提交:', value)
  }

  return (
    <form onSubmit={handleSubmit}>
      <input 
        type="text" 
        value={value}
        onChange={handleChange}
      />
      <button type="submit">提交</button>
    </form>
  )
}
```

### 5.2 事件绑定优化

```jsx
// ❌ 不推荐：每次渲染都创建新函数
function List({ items }) {
  return items.map(item => (
    <div key={item.id} onClick={() => handleClick(item.id)}>
      {item.name}
    </div>
  ))
}

// ✅ 推荐1：使用 useCallback
function List({ items }) {
  const handleClick = useCallback((id) => {
    console.log('clicked:', id)
  }, [])

  return items.map(item => (
    <div key={item.id} onClick={() => handleClick(item.id)}>
      {item.name}
    </div>
  ))
}

// ✅ 推荐2：使用 data-* 属性
function List({ items }) {
  const handleClick = (e) => {
    const id = e.currentTarget.dataset.id
    console.log('clicked:', id)
  }

  return items.map(item => (
    <div key={item.id} data-id={item.id} onClick={handleClick}>
      {item.name}
    </div>
  ))
}

// ✅ 推荐3：抽取子组件
function Item({ item, onClick }) {
  return (
    <div onClick={() => onClick(item.id)}>
      {item.name}
    </div>
  )
}

const MemoizedItem = React.memo(Item)

function List({ items }) {
  const handleClick = useCallback((id) => {
    console.log('clicked:', id)
  }, [])

  return items.map(item => (
    <MemoizedItem key={item.id} item={item} onClick={handleClick} />
  ))
}
```

## 六、面试高频问题

### Q1: React 事件和原生事件的区别？

**回答要点**：

1. **命名方式**
   - React：驼峰式 `onClick`、`onChange`
   - 原生：小写 `onclick`、`onchange`

2. **事件对象**
   - React：合成事件（SyntheticEvent），跨浏览器兼容
   - 原生：原生事件对象，浏览器差异

3. **事件注册**
   - React：事件委托到 root（React 17+）或 document（React 16）
   - 原生：直接注册在 DOM 元素上

4. **阻止默认行为**
   - React：必须显式调用 `e.preventDefault()`
   - 原生：可以 `return false`

```jsx
// React
<a href="#" onClick={(e) => {
  e.preventDefault() // 必须显式调用
}}>链接</a>

// 原生
<a href="#" onclick="return false">链接</a>
```

### Q2: React 17 事件系统的改进？

**关键变化**：

1. **事件委托位置改变**
   ```javascript
   // React 16: 委托到 document
   document.addEventListener('click', handler)
   
   // React 17: 委托到 root 容器
   rootNode.addEventListener('click', handler)
   ```

2. **移除事件池**
   - 不再需要 `e.persist()`
   - 可以在异步代码中直接使用事件对象

3. **onScroll 不再冒泡**
   ```jsx
   // React 17+ onScroll 不会冒泡，符合原生行为
   <div onScroll={handleScroll}>
     <div onScroll={handleInnerScroll}>
       内容
     </div>
   </div>
   ```

4. **更接近原生事件**
   - `onFocus`/`onBlur` 使用原生 `focusin`/`focusout`
   - 减少了与原生事件混用的问题

### Q3: 如何在 React 中使用原生事件？

```jsx
function Demo() {
  const buttonRef = useRef(null)

  useEffect(() => {
    const button = buttonRef.current
    
    const handleNativeClick = (e) => {
      console.log('原生事件')
    }
    
    // 添加原生事件监听
    button.addEventListener('click', handleNativeClick)
    
    // 清理
    return () => {
      button.removeEventListener('click', handleNativeClick)
    }
  }, [])

  const handleReactClick = () => {
    console.log('React 事件')
  }

  return (
    <button ref={buttonRef} onClick={handleReactClick}>
      点击
    </button>
  )
}

// 点击输出顺序：
// React 17+:
// 1. 原生事件（在 button 上触发）
// 2. React 事件（冒泡到 root 后触发）
```

**注意事项**：

```jsx
useEffect(() => {
  const handleDocumentClick = (e) => {
    console.log('document click')
  }

  document.addEventListener('click', handleDocumentClick)

  return () => {
    document.removeEventListener('click', handleDocumentClick)
  }
}, [])

const handleReactClick = (e) => {
  e.stopPropagation() // ⚠️ 只阻止 React 事件冒泡
  // 原生事件仍会触发，因为它先执行
}

// 如需阻止所有事件：
const handleReactClick = (e) => {
  e.nativeEvent.stopImmediatePropagation() // 阻止所有后续监听器
}
```

### Q4: 为什么不能在 React 中使用 return false 阻止默认行为？

```jsx
// ❌ 在 React 中不工作
<a href="https://example.com" onClick={() => {
  return false // 无效！
}}>链接</a>

// ✅ 必须显式调用
<a href="https://example.com" onClick={(e) => {
  e.preventDefault() // 正确
}}>链接</a>
```

**原因**：

1. React 事件处理函数的返回值不会被用来阻止默认行为
2. `return false` 是 jQuery 时代的语法糖
3. React 采用更明确的 API，避免隐式行为

### Q5: 事件处理函数中 this 指向问题？

```jsx
class Button extends React.Component {
  constructor(props) {
    super(props)
    this.state = { count: 0 }
    
    // 方案1：构造函数中 bind
    this.handleClick1 = this.handleClick1.bind(this)
  }
  
  // 问题：this 为 undefined
  handleClick1() {
    this.setState({ count: this.state.count + 1 })
  }
  
  // 方案2：类属性 + 箭头函数（推荐）
  handleClick2 = () => {
    this.setState({ count: this.state.count + 1 })
  }
  
  render() {
    return (
      <div>
        {/* 方案3：箭头函数包裹（不推荐，每次渲染创建新函数） */}
        <button onClick={() => this.handleClick1()}>
          方案3
        </button>
        
        {/* 方案4：bind（不推荐，每次渲染创建新函数） */}
        <button onClick={this.handleClick1.bind(this)}>
          方案4
        </button>
        
        {/* 推荐：使用类属性 */}
        <button onClick={this.handleClick2}>
          推荐方案
        </button>
      </div>
    )
  }
}

// 函数组件（推荐）：无 this 问题
function Button() {
  const [count, setCount] = useState(0)
  
  const handleClick = () => {
    setCount(count + 1)
  }
  
  return <button onClick={handleClick}>点击</button>
}
```

## 七、性能优化实践

### 7.1 事件监听优化

```jsx
// ❌ 问题：大量 DOM 节点绑定事件
function BadList({ items }) {
  return (
    <div>
      {items.map(item => (
        <div 
          key={item.id}
          onClick={() => handleClick(item)}
        >
          {item.name}
        </div>
      ))}
    </div>
  )

// ✅ 优化：利用事件委托
function GoodList({ items }) {
  const handleClick = (e) => {
    const id = e.target.closest('[data-id]')?.dataset.id
    if (id) {
      const item = items.find(i => i.id === id)
      console.log('clicked:', item)
    }
  }

  return (
    <div onClick={handleClick}>
      {items.map(item => (
        <div key={item.id} data-id={item.id}>
          {item.name}
        </div>
      ))}
    </div>
  )
}
```

### 7.2 防抖和节流

```jsx
import { useMemo, useCallback } from 'react'
import { debounce, throttle } from 'lodash'

function SearchInput() {
  // ❌ 错误：每次渲染都创建新的防抖函数
  const handleChange = debounce((e) => {
    console.log(e.target.value)
  }, 300)

  // ✅ 正确：使用 useMemo
  const debouncedSearch = useMemo(
    () => debounce((value) => {
      console.log('搜索:', value)
    }, 300),
    []
  )

  const handleChange = (e) => {
    debouncedSearch(e.target.value)
  }

  // 清理
  useEffect(() => {
    return () => {
      debouncedSearch.cancel()
    }
  }, [debouncedSearch])

  return <input onChange={handleChange} />
}

// 节流示例
function ScrollContainer() {
  const throttledScroll = useMemo(
    () => throttle(() => {
      console.log('滚动中...')
    }, 100),
    []
  )

  useEffect(() => {
    return () => {
      throttledScroll.cancel()
    }
  }, [throttledScroll])

  return (
    <div onScroll={throttledScroll}>
      {/* 内容 */}
    </div>
  )
}
```

## 八、总结

### 核心要点

1. **合成事件**：React 实现的跨浏览器兼容的事件系统
2. **事件委托**：React 17+ 委托到 root，React 16 委托到 document
3. **事件流**：支持捕获和冒泡，可以通过 `e.stopPropagation()` 阻止
4. **事件池**：React 16 有事件池优化，React 17 移除
5. **性能优化**：合理使用 useCallback、事件委托、防抖节流

### 面试技巧

1. **基础层**：能说清楚合成事件是什么，与原生事件的区别
2. **原理层**：理解事件委托机制，能画出事件流程图
3. **实战层**：遇到过的事件相关问题和解决方案
4. **版本层**：了解 React 17 的改进，能对比新老版本差异
